# Game flow: game mode, teams, hero select, EOS online

Paths under `Source/ZeroLock/` unless stated.

## Game mode: `AZero_BaseGameModeBase` (`Gamemode/`)
- `AGameModeBase` (no MatchState/warmup/rounds). `bUseSeamlessTravel=true`. TDM BP: `Content/ZERO/BP/GameMode/BP_TDMGameMOde`.
- `BeginPlay`: 1 s looping `UpdateGameTime` → `GS->IncrementGameTime()` (count-up, no limit). No online login here any more (see EOS / online).
- `PostLogin` → `AssignTeam` (smaller team, Red wins ties) → `PS->SetTeamID`, `GS->AddPSToTeamArray`.
- `ChoosePlayerStart` (`:93`): random `AZero_BasePlayerStart` with matching `TeamID`; writes `Character->StartLocation`, `PC->ServerSetStartLocation`.
- `SpawnDefaultPawnFor` (`:142`): `PC->SelectedHeroClass` or `DefaultHeroClass`.
- Death: `AZeroLockCharacter::HandleDeath` → server RPC `ServerHandleDeath(PC)` → `GM->HandlePlayerDeath`: first `DeadPawn->OnServerPreDeath` (native multicast, server; Doorman's hotel sends its guest back to the map here), then victim death, kill to `DeadPawn->LastHitCharacter` + `GS->AddKill(team)`, assists from `AssistListCharacters` (`AssistWindow` 5 declared, unused), `DeadPawn->Death()`, **3 s hard-coded** respawn timer → `RespawnPlayer` → `ResetCharacter()` on the **same pawn** (never destroyed/respawned).
- No win condition, score limit or match end; `Killed()` empty.
- `GlobalDefaultGameMode` in `DefaultEngine.ini` is the template `ZeroLockGameMode` (only `InitGlobalData`, BP_ThirdPersonCharacter). The real GM is set per map.

## Game state: `AZero_BaseGameState`
- Replicated: `TeamRedScore`/`TeamBlueScore` (no OnRep), `TeamRedArray`/`TeamBlueArray` (OnRep broadcasts only `.Last()`), `myGameTime` (OnRep formats MM:SS into `UZL_VM_GameState`).
- `RefreshTeamLists`/`ProcessTeamUpdate`: one `UZL_VM_PlayerInfo` per PS, split ally/enemy relative to the first local PC's PS.
- `ETeamID { TeamNull=0, TeamBlue, TeamRed }` (`ZeroLock.h:46`). `AZero_BasePlayerStart` adds `TeamID`.
- `UZero_BaseGameInstance` (BP `BP_ZeroGameInstance`): holds `CharacterDataTable`.

## Hero select
- Data: `FHeroTableRow{TSoftObjectPtr<UZL_Character_Data_Asset>}`; asset has CharacterName, Description, `CharacterClass`, DisplaySeletalMesh (sic), DisplayAnimation, Icon, IconColor (`CharacterSelector/ZL_Character_Data_Asset.h`). Table `Content/ZERO/UI/BP/CharacterSelector/DT_HeroList`.
- `UZL_CharacterSelectionSubsystem` (GameInstance) async-loads rows → `UZl_CharacterSelectionVM` (CoreRedirect for the lowercase l in `DefaultEngine.ini:78`).
- `AZL_CharacterSelector_Actor` (`BP_CharacterSelector`): preview mesh + SceneCapture2D (`RT_CharacterSelector`, show-only list = the mesh); on change sets mesh/anim and ability icons from the CDO (`SecondryFireAbility`, `Ability_1`, `Ability_2`, `UltimateAbility` `IconImage`); mouse X rotates the spring arm. Starts with **no mesh**, and a null hero clears mesh, name and icons. `UZL_HeroSelectionScreen::NativeOnActivated` sets the VM's current hero to null on every open, because the VM persists on the game instance and re-hovering the same hero wouldn't fire `OnCharacterChanged`.
  - Lighting: own `KeyLight` / `FillLight` / `RimLight` point lights (candelas) on **lighting channel 1**, and `PreviewMesh` receives channel 1 only, so level lights don't affect it. The sky light still adds ambient. Capture exposure is manual (EV 0, no physical camera) + `ExposureBias`, because histogram auto exposure on a nearly empty frame changes per hero.
  - Pose: `UZL_Character_Data_Asset::DisplayAnimationPoseTime` >= 0 freezes `DisplayAnimation` on that frame (`SetPosition` + `Stop`); negative loops it. The Deadlock imports ship single-frame hero-select poses: `A_Apollo_ui_hero_select`, `A_Lash_ui_pose` / `A_Lash_hero_pose`, `A_Pocket_ui_hero_select` (a calm walk; `A_Pocket_ability_barrage_start` at ~0.9 s is more dynamic), `A_TheDoorman_ui_hero_select` (row `TheDoorman` → `DA_TheDoorman_Hero`, pose time 0, icon `Hotel_Guest`, preview settings copied from Pocket and not yet tuned). `ui_hero_spicy_idle` (Apollo, Pocket) are 5 s idle loops. Facing differs per pose. Current yaws: Apollo 110, Lash -105, Pocket -60 (`ability_barrage_start` @ 0.9 s); all FOV 35, pitch 6, arm 480-500, rim = icon colour.
  - `FZL_HeroPreviewSettings` (`CameraYaw` = the spring-arm yaw the mouse sway centres on, `CameraPitch`, camera arm length/height/FOV, exposure bias, key/fill/rim colour, intensity, location relative to the mesh; camera is on +Y looking -Y; `bRimUsesIconColor`): the actor's `DefaultPreviewSettings`, overridden per hero by `UZL_Character_Data_Asset::bOverridePreviewSettings` + `PreviewSettings`, applied in `ApplyPreviewSettings`.
- **Pick on join** (`AZero_BaseGameModeBase::bPickHeroOnJoin`, per game mode BP, default false, replicated as `AZero_BaseGameState::bPickHeroOnJoin`): players arriving by login or (seamless) travel, so hosts and joiners alike, get **no pawn** until they pick.
  - `GenericPlayerInitialization` clears `SelectedHeroClass`, so a controller kept across seamless travel picks again. `PlayerCanRestart` is false while `IsWaitingForHeroPick` (mode on, no pawn, no `SelectedHeroClass`).
  - `HandleStartingNewPlayer` sends `ClientSetViewTarget(<team PlayerStart>)` so the camera looks out from the spawn.
  - HUD: `AZL_HUDClass::UpdateInitialHeroPick` polls every 0.2 s from BeginPlay until there's a pawn. It opens the hero select (`OpenHeroSelect` lets it through without `bAllowHeroSwap` while pawnless) and reopens it if closed, unless `PC->HasPendingHeroRequest()` (a `RequestHero` less than `HeroRequestTimeout` 3 s ago). The timer stops when the game state isn't `AZero_BaseGameState` or the mode is off.
  - Click → `AZero_BasePlayerController::RequestHero` → `ServerSwapHero` (allowed without `bAllowHeroSwap` while waiting) → `SwapHero` → `RestartPlayer` → `SpawnDefaultPawnFor` spawns `SelectedHeroClass` at a team start. Possession moves the view to the pawn.
  - The Game-layer HUD pushed in BeginPlay had no pawn, so `HandleHeroReady` rebuilds it for the first pawn too (`bWaitingForHeroPick`).
  - With the mode off: `ServerSetSelectedHero` → `SelectedHeroClass` → `SpawnDefaultPawnFor` is still the only pre-spawn path, nothing calls it, and everyone spawns `DefaultHeroClass` at login.
- **In-game hero swap** (H key): **per game mode**. `AZero_BaseGameModeBase::bAllowHeroSwap` (default false; set it on the game mode BP) is copied to the replicated `AZero_BaseGameState::bAllowHeroSwap` in `InitGameState`. `AZL_HUDClass::OpenHeroSelect` won't open without it (H and pad both), and `ServerSwapHero` rejects swaps without it. `AZL_HUDClass` (`BP_BAseHUD`) owns the UI. `SetupHeroSelectInput` builds an `UInputAction` + `UInputMappingContext` at runtime (no assets; key `HeroSelectKey`, default H, mapping priority 1), `EnableInput` on the HUD, binds Started → `ToggleHeroSelect`. It lives on the HUD so it survives pawn swaps. `OpenHeroSelect` pushes `HeroSelectWidgetClass` onto `UI.Layer.Menu`, spawns a local `HeroSelectPreviewClass` (`BP_CharacterSelector`) at `HeroSelectPreviewLocation` (0,0,-10000) for the render target, and shows the cursor; deactivating the widget undoes all of it.
  - Widget: `Content/ZERO/UI/BP/CharacterSelector/WBP_HeroSwap`, a copy of `WBP_HeroSelector` without the EOS Login/ServerTravel nodes, with `bSwapHeroOnClick` and `bIsBackHandler` on, and `Button_65` "Close" → `DeactivateWidget`. Closes on: Close button, Esc/Back, `CloseKey` (H; menu input mode blocks the HUD's binding, so `UZL_HeroSelectionScreen::NativeOnKeyDown` handles it, with focus on the tile list via `NativeGetDesiredFocusTarget`), or picking a hero.
  - Optional pad `AZL_HeroSwapPad` (`CharacterSelector/ZL_HeroSwapPad.h`, `BP_HeroSwapPad`): box trigger that calls the HUD's `OpenHeroSelect`, and `CloseHeroSelect` on step-off if it opened it. Pawns younger than `IgnoreNewPawnTime` (1 s) don't open it, so the pawn you just swapped into doesn't reopen it.
  - Clicking a tile (`UZL_HeroSelectionScreen::HandleOnSelectionChanged`, only with `bSwapHeroOnClick`) → `RequestHero` → `ServerSwapHero(CharacterClass)` → if `AZero_BaseGameModeBase::bHeroSwapRequiresPad` (default false: swap anywhere), server checks the pawn is on some pad (`IsPawnOnPad`: overlap, or position inside the box + `ServerCheckTolerance` 150 cm, because the server's overlap state for a remote client's Mover pawn is unreliable) → `AZero_BaseGameModeBase::SwapHero`: sets `SelectedHeroClass`, destroys the old pawn, spawns the new class at the same spot/yaw, keeps the old `StartLocation`, possesses it. Team, K/D/A and name live on the PlayerState, which is kept, so the team never changes. Fresh pawn = fresh ASC: items, souls, ability levels and cooldowns are not carried over.
  - A pawn spawned mid-match runs BeginPlay inside `SpawnActor`, **before** it is possessed, so `IsLocallyControlled()` checks in BeginPlay are false. (At match start, pawns spawn before the world begins play, so BeginPlay runs after possession; that's why it worked there.) Local-only setup must also run from `AZeroLockCharacter::NotifyHUDHeroReady` (from `PossessedBy` / `OnRep_PlayerState` / `OnRep_Controller`, once locally controlled with a PlayerState): it calls `UZL_AbilityUIManagerComponent::BindToLocalHero` (ASC events + replay specs, guarded to run once), hides `OverHeadDisplay`, then `AZL_HUDClass::HandleHeroReady`.
  - HUD rebind: for any pawn after the first, the HUD waits until `PC->GetPawn()` is the new hero (resolvers use `GetOwningPlayerPawn()`; on the host `PossessedBy` runs before `SetPawn`, and on clients the pawn's PlayerState can arrive before the controller's Pawn), then creates a **fresh** `PlayerInGameHUD` instance, adds it with `AddWidgetInstance`, then removes the old one once the stack has switched. Don't use `ClearWidgets` + `AddWidget` here: the stack pool hands back the same instance (old pawn bindings, since `NativeOnInitialized` runs once) or the one still being removed (HUD disappears).
  - Not validated: any non-abstract `AZeroLockCharacter` subclass is accepted (not checked against `DT_HeroList`); no swap cooldown, and with the pad not required, swapping works anywhere, mid-fight included (full heal).

## EOS / online
Lyra-style: **CommonUser** plugin (copied from Lyra 5.8 into `Plugins/CommonUser`, OSSv1, `COMMONUSER_OSSV1=1`) + a game subclass. No CommonGame (our CommonUI layers stay on `AZL_HUDClass`).

**Config split (like Lyra's `LyraGameEOS`)**:
- `Config/DefaultEngine.ini`: `[OnlineSubsystem] DefaultPlatformService=Null`, default IpNetDriver, AESGCM packet handler (inactive without a token), `[/Script/CommonUser.CommonSessionSubsystem] bUseLobbiesDefault/bUseLobbiesVoiceChatDefault=true`. PIE and the plain `ZeroLock` target run here (Null OSS, LAN sessions).
- `Config/Custom/EOS/DefaultEngine.ini`: everything EOS. `DefaultPlatformService=EOS`, `[OnlineSubsystemEOS]`, `NetDriverEOS` (P2P) for Game + Beacon net drivers with IpNetDriver fallback, EOS packet handler, `EOSSettings` (EAS + Connect + RTC, `bUseEOSSessions`, overlays, persistent auth, artifacts). **It holds the EOS client credentials: gitignored (public repo), share it privately. Never copy them into docs, logs or chat.** Project Settings edits to the EOS plugin save into `Config/DefaultEngine.ini`, not here: move them by hand.
- Only used when CustomConfig is `EOS`: target `Source/ZeroLockEOS.Target.cs` (`CustomConfig = "EOS"`, makes staging include the folder) and/or the `-CustomConfig=EOS` command line. The engine is an **installed build**, so the target can't compile `CUSTOM_CONFIG` in (shared build env, `UEBuildTarget.cs:6651`). EOS needs `-CustomConfig=EOS` on the command line (editor, standalone, packaged Development). The command line override is compiled out of Shipping (`ALLOW_INI_OVERRIDE_FROM_COMMANDLINE`), so **Shipping + EOS needs a source engine** or the EOS sections moved back into the default config.
- EOS plugins (`OnlineSubsystemEOS`, `OnlineServicesEOS*`) stay enabled in the `.uproject` so the editor can run with `-CustomConfig=EOS`. `ZeroLock.Build.cs` no longer links `OnlineSubsystemEOS`/`SocketSubsystemEOS`; `P2PMODE` is gone.

**`UZL_SessionSubsystem`** (`Online/ZL_SessionSubsystem.h`, subclass of `UCommonSessionSubsystem`, so the base one isn't created):
- `Login()` → `UCommonUserSubsystem::TryToInitializeUser` (player 0, `CanPlayOnline`). EOS OSS `AutoLogin`: `-AUTH_TYPE=/-AUTH_LOGIN=/-AUTH_PASSWORD=` if given, else persistent auth, then account portal. Null logs in instantly. `RunAfterLogin` queues host/find/join until login finishes, so every call logs in first if needed.
- `HostMatch(MapPath, MaxPlayers)` / `HostMatchWithMode(..., Online|LAN|Offline)`: `UZL_HostSessionRequest` (adds `MapPath`, because our maps aren't "Map" primary assets, which CommonUser's `MapID` needs) → `HostSession` → create session (EOS lobby + presence + lobby voice) → `ServerTravel(Map?listen)`. Session name `NAME_GameSession`. From a standalone world, `HandleCreateSessionComplete` sets the current game mode's `bUseSeamlessTravel = false` first. A seamless travel never starts the listen net driver, so the host would advertise a lobby that nobody can connect to: the client's beacon works, then its `GameNetDriver` P2P connection gets "unknown socket" on the host.
- `QuickPlay(MapPath)`: CommonUser search, join the first result, else host. No map/mode filter (CommonUser default).
- `FindMatches()` → `GetLastSearchResults()` + `OnFindMatchesFinished`; `JoinMatch(Result)` / `JoinMatchByIndex(i)` → `JoinSession` (reservation beacon, then `ClientTravel` to the resolved connect string).
- `LeaveMatch()`: `CleanUpSessions()` + `OpenLevel(MainMenuMap)`.
- Invites / join-from-overlay (`OnUserRequestedSessionEvent`) → `JoinMatch`; platform "leave" (`OnDestroySessionRequestedEvent`) → `LeaveMatch`.
- Default mode: `Online` when the OSS isn't Null, `LAN` with Null (`GetDefaultOnlineMode`).
- Config (`[/Script/ZeroLock.ZL_SessionSubsystem]`, Engine ini): `DefaultMatchMap` (code default ThirdPersonMap, set to `/MoverExamples/Maps/L_CharacterMovementBasics` in `DefaultEngine.ini`; that's the real game map with `BP_TDMGameMOde`. ThirdPersonMap uses `MoverTestGamemode`, a plain `AGameModeBase` with no teams or hero pick), `MainMenuMap` (`/Game/ZERO/Levels/Lvl_MainMenu`), `DefaultMaxPlayers` 12, `ModeName` "TDM". `bUseBeacons` (CommonUser default true: party reservation beacon). Needs `[/Script/OnlineSubsystemUtils.PartyBeaconHost] bIsValidationStrRequired=false` (in `DefaultEngine.ini`, as in Lyra). Without it the host rejects every reservation, so joins fail with `UnknownError` and the host's beacon net driver dies, which makes every later join time out.
- Logs to `LogZLSession` + on-screen; CommonUser logs `LogCommonUser` / `LogCommonSession`.

**Console commands** (any world, PIE included):
| Command | Does |
|---|---|
| `ZL.Online.Login` | log in for online play |
| `ZL.Online.Host [MapPath\|-] [MaxPlayers] [online\|lan\|offline]` | host a listen-server match; no args = the current map (PIE prefix stripped), `-` = `DefaultMatchMap` |
| `ZL.Online.QuickPlay [MapPath]` | join the first match found, else host |
| `ZL.Online.Find` | search and print `[index] host \| mode map \| players \| ping` |
| `ZL.Online.Join <Index>` | join a result of the last Find |
| `ZL.Online.Leave` | destroy session, back to the main menu map |
| `ZL.Online.Status` | OSS, login state, session, net mode, map |

Without `-AUTH_*` args EOS AutoLogin uses persistent auth, then the Epic Account Portal (overlay; needs the Epic Games Launcher installed). Blueprint users: `WBP_HeroSelector` used to call `UZL_EOS_SubSystem::Login` on Construct and `ServerTravelAfterPlayersJoin` on `Button_65`. Those nodes were removed with the old subsystem (2026-10-19). Wire the new subsystem in if the menu should do online.

Tutorial / dev-only: `AZL_EOS_GameSession` (dedicated server, used only by `Developers/rpm86/EOSTEST/BP_EOSTESTGM`), `AZL_EOS_PlayerController` (used only by `BP_EOSPLayerController` in EOSTEST). `UZL_TelemetrySubsystem` moved to `Telemetry/` and is now the stats recorder (Telemetry.md); the game mode starts/ends its match and calls it on join/leave/hero pick/death. `UZL_EOS_SubSystem` and the dead `AZL_EOSGameSession` were deleted.

## Cheats (dev builds)
Code `Source/ZeroLock/{Public,Private}/Cheats/`. Server-authoritative, so listen-server clients can use them too.
- `UZL_CheatComponent` (default subobject `CheatComponent` on `AZero_BasePlayerController`): server RPCs, each refused in Shipping and while the **server's** `ZL.Cheat.Allow` is 0 (default 1; every accepted call logs `[Cheats]`). Toggles (`EZL_CheatToggle` GodMode / NoClip / NoCooldowns / InfiniteAmmo) are a replicated owner-only bitmask turned into loose tags `Zerolock.Cheat.*` (native `TAG_CHEAT_*`) on the current pawn's ASC by a 0.25 s poll on the server and the owning client (`SetLooseGameplayTagCount`, so respawns and hero swaps keep them). Effects: god mode → `UBaseCharAttributeSet` shows the damage number, takes nothing; no cooldowns → `UBaseGameplayAbility::ApplyCooldown` skips, charged abilities don't spend charges (enabling it also clears cooldowns); infinite ammo → `UZL_GA_WeaponFire::ApplyCost` spends nothing; noclip → Mover NoClip mode (Movement.md). Actions: `ServerRefill` (health, ammo, stamina, charges, cooldowns), `ServerAddSouls`, `ServerMaxAbilityLevels` (the four slotted abilities to `MaxAbilityLevel` 3 via `LevelUpAbility`), `ServerKillSelf`, `TeleportToCrosshair` (local camera trace → `ServerForceTeleport`), `ServerPlayAsHero` (`AZero_BaseGameModeBase::SwapHero`, ignores `bAllowHeroSwap`/pads), `ServerSpawnDummy`, `ServerRemoveDummies`.
- **Target dummies**: `ServerSpawnDummy(HeroClass (None = my hero), bEnemy, bImmortal, bStrafe)` spawns any hero `DummySpawnDistance` 600 cm in front, on the ground, facing you, possessed by `AZL_DummyController` (`AAIController`, `bWantsPlayerState`, PlayerState `SetIsABot`). Team: enemy = the other team (Red if you have none), ally = yours (can't be damaged). Immortal = loose `Zerolock.Cheat.Buddha` (health never below 1, numbers still show full damage). Health refills `HealDelay` 3 s after the last hit; a mortal dummy calls `ResetCharacter` `RespawnDelay` 3 s after dying, in place (no kill credit, `HandlePlayerDeath` isn't reached without a PlayerController). Strafe = `AZeroMoverPawn::SetBotMoveInput` ±1 right every `StrafeInterval` 1.2 s. Damage telemetry skips bots. Bot PlayerStates are in the game state's `PlayerArray`. `AZeroLockCharacter` uses `IsPlayerControlled()` in `InitializeFloatingStatusBar`/`NotifyHUDHeroReady`, so a bot on the host gets an overhead bar and no local-player HUD setup.
- **Menu** `UZL_CheatMenu` (`UCommonActivatableWidget` built entirely in C++, `UZL_CheatButton` = `UButton` with a native callback; no widget BP): `AZL_HUDClass` maps `CheatMenuKey` (0, number row) in its own runtime mapping context like the hero select key and pushes `CheatMenuClass` (default `UZL_CheatMenu`; not set up in Shipping) onto `UI.Layer.Menu`. Menu/NoCapture input + cursor; closes on 0 (`NativeOnKeyDown`), Esc (back handler) or Close. Two tabs (`UWidgetSwitcher`): **Cheats** = player toggles and actions, then a hero selector (`<` name `>`, entry 0 = "My Hero", then `DT_HeroList`; data assets load synchronously when the menu is first built) with Spawn as Enemy / Spawn as Ally / Play As, dummy options (Immortal, Strafe), Remove All Dummies. **Debug** = live readout (`UZL_CheatComponent::BuildDebugReadout`: net mode, emulation profile, ping, in/out KB/s and loss from the `UNetConnection` (clients only), pawn role, Mover rollbacks total and per second (`UZeroMoverComponent::GetRollbackCount`, counted in `HandleSimRollback`), mode, speed, position, stamina, air jumps/dashes, dash time left, status flags) with an "On-screen Readout" toggle (`bShowDebugOverlay`: the component ticks on the local player only and draws it with a keyed `AddOnScreenDebugMessage`, so it stays with the menu closed); cvar toggles `mover.debug.ShowCorrections/ShowTrail/ShowTrajectory/ShowTeleportDiffs/ShowInputArrows/ShowStateArrows`, `np.Debug.DrawServerPrimitives`, `ZL.Debug.CubeLog`; `stat fps/unit/net` buttons; network emulation presets Off / Average / Bad / BufferBloat (`SetNetEmulationProfile` → `NetEmulation.PktEmulationProfile` / `NetEmulation.Off`, this machine's outgoing packets; the highlighted one is only the last pick from the menu). Labels follow the replicated / cvar state every tick.
- Console (`ZL.Cheat.*`, same component, local player found like `ZL.Debug.*`): `God`, `NoClip`, `NoCooldowns`, `InfiniteAmmo` (`[1|0]`, none = toggle), `Refill`, `Souls [N=10000]`, `MaxAbilities`, `Teleport`, `Dummy [Hero|-] [enemy|ally] [strafe] [mortal]`, `ClearDummies`, `PlayAs <Hero>` (hero = part of the data asset's `CharacterName` or class name).

## Known issues
- Unvalidated server RPCs: `ServerSetSelectedHero` (any class), `ServerSetStartLocation` (any vector) (`Zero_BasePlayerController.cpp:10,20`), **`ServerHandleDeath` lets a client trigger death/kill credit/respawn** (`ZeroLockCharacter.h:256`, `.cpp:533`).
- `SpawnPawnDefault` derefs `NewPawn` on failure (`Zero_BaseGameModeBase.cpp:309`); `Instigator` is the old pawn (`:293`).
- Seamless travel: teams assigned only in `PostLogin` (no `HandleSeamlessTravelPlayer` override); no `Logout` override → stale team array entries. Team arrays can replicate before PS `TeamID` (`Zero_BaseGameState.cpp:149`).
- `AddKill` has no authority guard (`Zero_BaseGameState.cpp:12`).
- Character table loaded twice (`ZL_CharacterSelectionSubsystem.cpp:20-26` and `Zero_BaseGameInstance.cpp:24-26`). Frame-rate dependent `REase` in `AZL_CharacterSelector_Actor::Tick`.
- EOS tutorial classes: `EndSession` failure clears the wrong delegate handle (`ZL_EOS_GameSession.cpp:223`). Memory bug in `ZL_EOS_PlayerController.cpp:315`. (The title-file read at ~343 used `try`/`catch` + an unterminated `new char[]`. Game targets compile without C++ exceptions (C4530), so it broke packaging; it now converts with `FUTF8ToTCHAR` and an explicit length.)
- Online: no front end yet (console commands / BP calls only). Shipping builds can't turn EOS on (installed engine, see above).
- `Config/DefaultEngine.ini:43` malformed (`GameViewportClientClassName=...CommonGameViewportClient[/Script/Engine.GameEngine]`): CommonUI viewport client and the `NetDriverDefinitions` section placement may not apply as intended. Verify in editor.
