# UI (CommonUI + MVVM)

Code: `Source/ZeroLock/{Public,Private}/UI/` (65 classes). Widget BPs: `Content/ZERO/UI/BP/`. Styles: `Content/ZERO/UI/CommonStyles` (`CBS_*`, `CS_*`).

## Layering
- `AZL_HUDClass` (`UI/HUD/ZL_HUDClass`): local controller only. BeginPlay creates `BaseUILayer` (`WBP_BaseUILayout`) as `RootLayer`, then virtual `PushHUD()` pushes `PlayerInGameHUD` onto `UI.Layer.Game`, but only once there's a pawn, because the HUD's MVVM resolvers read it ("Resolver returned an invalid value" otherwise). Without one at BeginPlay (hero pick on join, a client whose pawn hasn't replicated) `HandleHeroReady` builds the HUD for the first `AZeroLockCharacter`, so the Game layer is empty during the join hero pick.
- `AZL_HUDClass` also owns the in-game hero select (H key, runtime-built input action, `Open/Close/ToggleHeroSelect`), see GameFlow.md "In-game hero swap".
- `AZL_MainMenu_HUD_Class` overrides `PushHUD` → `UI.Layer.Menu`, shows cursor.
- `UZL_BaseUILayout` (root, `UCommonActivatableWidget`): four BindWidget stacks `GameStack`, `MenuStack`, `ItemShopStack`, `PopUpStack` mapped by `FUITag` in `NativeOnInitialized`.
  - `PushWidgetToLayer(Tag, Class)`: pushes only if the layer is empty or its active widget is a different class (no toggle/remove).
  - `GetActivatedWidgetInLayer(Tag)`.
  - Input config: `ECommonInputMode::All`, mouse `CapturePermanently`.
- Layer tags (native, `ZL_UI_Tags.cpp`): `UI.Layer.Game`, `UI.Layer.Itemshop`, `UI.Layer.Menu`, `UI.Layer.PopUp`.
- Item shop / keybinding screens are opened from BP (`WBP_PlayerHUD`, `CommonActivatableWidgetSwitcher_0`, FlipFlop on the B and K key events), not C++. Opening sets UI-only input, which calls `SetIgnoreInput(true)` and stops those key events at the viewport, so `UZL_ItemShop_Base` turns viewport input back on and removes the pawn's mapping context while active (`AZeroMoverPawn::SetGameplayInputEnabled`). `read_graph_dsl` doesn't show this graph's FlipFlop, so don't rewrite it with `write_graph_dsl`. No pause, scoreboard or lobby screens exist.

## MVVM
Two ways to attach a viewmodel:
1. **Resolvers** (widget BP Viewmodels panel, creation type Resolver):

| Resolver | Returns |
|---|---|
| `UZL_VMCR_Attributes` | owning pawn's `AZeroLockCharacter::GetVM_Attributes()` |
| `UZL_AbilitiesResolver` | `AbilityUIManager->GetAbilitiesViewModel()` |
| `UZL_AbilitesTimerResolver` (sic) | `AbilityUIManager->GetAbilityProgressionStack()` |
| `UZL_GameStateResolver` | `AZero_BaseGameState::GetGameStateVM()` |
| `UZL_VMCR_KeyBindingScreen` | new `UZL_VM_KeyBindingList` for the local player |

2. **Manual injection**: `SetViewModel(VM)` → `UMVVMSubsystem::GetViewFromUserWidget(this)->SetViewModel(FName("<VMName>"), VM)`. The FName must match the BP's viewmodel name: `ZL_VM_Attributes`, `ZL_VM_AbilityIcon`, `ZL_VM_ChargePercent`, `ZL_VM_AbilityTimerProgressBar`, `ZL_VM_PlayerInfo`, `ZL_VM_KeyBindingRow`, `Zl_CharacterSelectionVM`. Used for list entries, player boxes, world-space widgets, tooltips.

VM property pattern: `UPROPERTY(BlueprintReadOnly, FieldNotify, Setter, Getter)` + `UE_MVVM_SET_PROPERTY_VALUE`; derived values are `UFUNCTION(BlueprintPure, FieldNotify)` re-broadcast from setters.

### Who owns which VM
| VM | Owner | Fed by |

The owning player's Stamina comes from `MoverStaminaChanged` (predicted), not the lagging attribute |
| `UZL_VM_AbilitiesContainer` (4 `UZL_VM_AbilityIcon` slots), `UZL_VM_ProgressionStack` | `UZL_AbilityUIManagerComponent` on the character | ASC events (below) and `BaseGameplayAbility` timers |
| `UZL_VM_GameState` (AllyTeam, EnemyTeam, FormattedGameTime), `UZL_VM_PlayerInfo` per player | `AZero_BaseGameState` | game state |
| `UZl_CharacterSelectionVM` | `UZL_CharacterSelectionSubsystem` (game instance) | hero select |
| `UZL_VM_ChargePercent` | set by `BaseGameplayAbility` into `VM_Attributes->VM_ChargePhase` | charged abilities (perfect window) |

### `UZL_AbilityUIManagerComponent`
- BeginPlay: creates 4 slots (Secondary, Ability1, Ability2, Ultimate) keyed by input tags `ZerolockGameplayTagsForBinding::TAG_INPUT_SECONDRY/ABILITY_1/ABILITY_2/ULTIMATE`, then `BindToLocalHero()` (once; also called from `AZeroLockCharacter::NotifyHUDHeroReady` for pawns possessed after BeginPlay, e.g. hero swap). Locally controlled: binds ASC `OnAbilityUpgraded`, `OnNewAbilityAdded`, `OnActiveGameplayEffectAddedDelegateToSelf`, then replays existing specs.
- `OnAbilityAdded`: slot found by spec `DynamicSpecSourceTags`; fills icon, name, descriptions (base + L1–3), charges (`AbilityCharges_N`/`MaxCharges_N` by `EGameplayAbilitySlot`, plus the slot's recharge tag), cooldown tags, `StackTag`. Re-runs for the same spec (rebroadcasts), so each delegate binding removes this component's old one first.
- Cooldowns: 0.033 s looping `RefreshCooldowns` timer while any cooldown or recharge tag is active. Recharge time → `UZL_VM_AbilityIcon::UpdateRecharge` (`RechargePercent`, `bIsRecharging`); with 0 charges the cooldown fields (`CooldownPercent/Text`, `bIsOnCooldown`) show the next-charge timer instead of the lockout.
- `WBP_AbilityIcon` is round and 144 across. `AbilityIcon` is a `UZL_RoundImage` inside `AbilitySize` (SizeBox, 144 x 144: this sets the bar's size; 2 padding each side in `WBP_Abilitybar`, where `Ability2` and `Ability3` sit 16 higher through their render translation for a slight arc), inset by 20 slot padding so the image sits inside the circle (104 across), bindings unchanged. `AbilityBG` is the 144 circle via its designer brush and carries the 2 wide outline. `AbilityLevel` text is hidden (Collapsed, opacity 0; binding kept). Button `MinWidth`/`MinHeight` are 0 (they were 180, a grey square behind the icon and the real size of each slot) and `Style` is `BCS_AbilityIcon` (`CommonStyles/`, every brush NoDrawType, no padding): without a style the button draws the default grey background. All of these are also set on the four instances in `WBP_Abilitybar`, which keep their own values.
- `UZL_RoundImage` (`UI/HUD/`, `UImage` subclass): for round visuals on MVVM-bound images. It only overrides the paint (`SZL_RoundImage` draws the current brush as a rounded box, which clips the texture), so a binding like `IconTexture` → `MakeBrushFromTexture` → `Brush` keeps working and still comes out round. `RadialProgress` (0-1, clockwise from the top, 0 and 1 draw nothing) paints a `RadialColor` sweep over the part not yet reached, `RadialOverscan` extends it past the image. `WBP_AbilityIcon` binds `AbilityIcon.RadialProgress ← ZL_VM_AbilityIcon.CooldownPercent` (it was `RenderOpacity`), overscan 20 so the sweep covers the whole 144 circle. Don't replace a bound image with a C++ fed one to change how it looks. Size it with a parent SizeBox, because bound brushes bring their own `ImageSize`.
- `UZL_HUD_AbilityIcon` follows the VM's `AbilityCharges/MaxAbilityCharges/bHasCharges` field notifications: charged abilities get stamina-style pips in BindWidgetOptional `ChargePipBox` (`WBP_AbilityIcon`, under the icon): one per max charge, full ones `ChargeFullColor`, the recharging one filling with `RechargePercent` in `ChargeRechargingColor` (also `ChargePipStyle/Size/Spacing`). Without `ChargePipBox` it falls back to the old `ChargeBar` material (`CurrentStep`, `NumSteps`, collapsed in the WBP now) + `AbilityChargesText`. Pip code is shared with the stamina bar: `ZLPipBar::Refresh` (`UI/HUD/ZL_PipBar.h`).
- Upgrades: click HUD icon → `IncrementAbilityLevel` → `Server_UpgradeAbility(Class, Level)` → server sets `Spec.Level`, `MarkAbilitySpecDirty`.
- Ability timers: `BaseGameplayAbility` calls `AddProgressBarVM` / `SetProgressionLevel` / `RemoveProgressBarVM`.

## Data paths
- Health/ammo: GAS → character → `UZL_VM_Attributes` → BP bindings. Barrier: `UMyZL_BasePlayerHealthBar` (C++ parent of `ZERO/UI/BP/Widgets/WBP_PlayerHealth`) adds it at runtime without BP changes: in `NativeOnInitialized` it finds the first `UProgressBar` (or `HealthBarName`), which must sit in an Overlay, and adds a barrier bar (the health bar's style, transparent background, `BarrierColor` light blue, `RightToLeft`, percent = barrier / max health) and a "+N" text (right, `BarrierTextSize` 14) to that overlay; `NativeTick` collapses both at 0. Reads the widget's MVVM viewmodel `ZL_VM_Attributes`, else the owning pawn's. The overhead bar (`WBP_OverHeadDisplay`) doesn't show barrier. Overhead bar for remote characters via `InitializeFloatingStatusBar` → `UZL_OverHeadDisplay`.
- Stat panels (`UZL_WeaponStat`, `UZL_SpiritStat`, `UZL_VitalityStat` with `UZL_Stat_Box`): **not MVVM**, bind `ASC->GetGameplayAttributeValueChangeDelegate` directly on `GetPlayerPawn(0)` at init.
- K/D/A: `UZL_KDA_Bar` ← `AZero_BasePlayerState::OnKills/Deaths/AssistsChanged` (binds immediately on authority, else via `AZero_BasePlayerController::OnPSInit`).
- Timer: `UZL_HUD_GameTimer` ← `AZero_BaseGameState::OnGameTimeUpdated`.
- Team bar (`WBP_GameState`, inside `WBP_PlayerHUD`): ally cards | match timer (`CommonTextBlock_107`, MVVM-bound to `FormattedGameTime`) | enemy cards. `UZL_GameState_Bar` (`OnAllyTeamChanged/OnEnemyTeamChanged` → `RebuildTeam`) creates one `PlayerIconClass` card per player (`CardSpacing` 6), calls `SetIsAlly`, then `SetViewModel`. `PlayerIconClass` = `WBP_PlayerInfo` (anything not a `UZL_PlayerInfoBox` falls back to the native class). The `WBP_GameState` instance inside `WBP_PlayerHUD` stores its own `PlayerIconClass` override: change it there too, the class default alone doesn't reach the running HUD.
  - Bar layout: `SizeBox_0` in `WBP_GameState` fixes it at 1280 wide (2/3 of the 1920 UI width at 16:9), centred. Ally and enemy lists are Fill slots (ally right aligned, enemy left aligned), so the timer stays centred with uneven teams. Card = fixed 90 wide (`SizeBox_2`): 72 portrait + 10 bar + 8 padding. With `CardSpacing` 6, six cards take 576 of the ~590 per side; don't grow the card without shrinking something else.
  - Card extras: circle portrait, bottom to top in `Overlay_0`: `PortraitBackground` (Border, hero `IconColor` x 0.55 disc), `PlayerIcon` (a `UZL_RoundImage`, bindings unchanged), `IconOutline`. `IconOutline` gets a transparent circle brush whose outline is the player's real team colour (`TeamRedColor` / `TeamBlueColor`, polled from `PS->TeamID`, `IconOutlineThickness` 3, `DeadColor` when dead), not ally/enemy. `KDABox` (name + K/D/A overlay, `StatsRow` inside it) stays collapsed unless `AZL_HUDClass::IsShowingTeamStats()`, set by `AZeroLockCharacter::UIInfoPressed/Released` (`IA_UIInfo`, hold Tab, which also shows the cursor for ability upgrades). `UZL_GameState_Bar` calls `SetHealthBarMirrored(bAlly)`: cards left of the timer get the bar on the left of the portrait, padding swapped, shear negated. It uses `ShiftChild`, so it must run before the card is added to a panel.
  - `WBP_PlayerInfo` (parent `UZL_PlayerInfoBox`, all widgets `BindWidgetOptional`): row `HorizontalBox_1` = `SizeBox_1` (fixed 100×100: the WBP's MVVM binding `Icon → MakeBrushFromTexture → PlayerIcon.Brush` makes a 0×0 brush from a null icon and collapsed the row) → icon overlay (`PlayerIcon`; `ApplyHero` also writes the hero icon into `UZL_VM_PlayerInfo::SetIcon` so that binding shows it; `PlayerIcon_1` is a collapsed placeholder duplicate) + `SizeBox_0` (14 wide, padding L8/T4/R4/B4) with the vertical `HealthBar` beside it, as tall as the icon. The bar copies the player HUD bar's style (`WBP_PlayerHealth` `ProgressBar_97`: grey 0.63 background, fill R0 G0.45 B0.01, `BottomToTop`) and keeps the card's −13 shear. Name, then K/D/A under the row. With a designer layout the C++ only sets the icon texture, the dead tint on the icon, health percent and texts; it doesn't recolour the bar.
  - `UZL_PlayerInfoBox` as a plain C++ class (no designer tree; currently unused) builds its own card in `NativeOnInitialized` (`BuildCard`): team-coloured rounded `PortraitFrame` (`AllyColor` blue / `EnemyColor` red, `DeadColor` grey when dead) → `PortraitSize` 52 square → `PortraitBackground` (hero `IconColor` × 0.55) → `PlayerIcon`; under it a `HealthBar` the card width (`HealthBarHeight` 6, `AllyHealthColor` / `EnemyHealthColor`) and the `PlayerName`. "Built card" = `PortraitFrame` exists.
  - Data comes from `UZL_VM_PlayerInfo::GetOwningPlayerState()` (set in `AZero_BaseGameState::ProcessTeamUpdate`), polled in `NativeTick`: hero = `FindHeroData` (the `DT_HeroList` asset whose `CharacterClass` is the closest parent of the pawn class, re-resolved when the pawn class changes, e.g. hero swap; `DefaultHeroIcon` if none), health from the pawn's ASC (`CurrentHealth/MaximumHealth`, replicated to everyone), dead = no pawn or health ≤ 0, name and K/D/A straight from the PlayerState (so they update live). `AZero_BasePlayerState::PlayerImage` is never set and not used.
  - `UZL_HUD_TeamList_View` is the old, effectively dead version.
- Active items: `UZL_HUD_ActiveItemBar` (`UI/HUD/`, built in C++, no WBP), placed in `WBP_PlayerHUD` as `ActiveItemBar` in `Overlay_40` (`UZL_HUD_PlayerBase` binds it, optional): move it in the widget editor. It builds its slots in `RebuildWidget` as well, so it draws there; `Slots` is `Transient` so that design-time copy is never saved. One `UZL_RoundImage` per key (`SlotSize` 64): item icon, radial sweep and seconds from the item's cooldown tag, key name from `QueryKeysMappedToAction` (so remaps show; refreshed when an item changes, empty slots included). While the cursor is out (Tab held) items drag between slots through `ServerMoveActiveItem`; the slot under the pointer comes from the row maths in `FindSlotAt`, so changing the layout means changing that too. The move shows once the server's answer arrives. Releasing Tab cancels a drag. Polls the owning pawn in `NativeTick`, so a hero swap needs no rebind; transparent with no active items. Lives in the same overlay as the rest of the HUD, so the shop hides it.
- Item icon shape: `UZL_ITemIcon` curves `ItemIcon` (not the tile behind it) by what the item is: top corners for imbue, bottom corners for active, all four for both, `CornerRadius` 40 at the top of its `.cpp`. It draws the brush as a per-corner `RoundedBox`, which clips the texture.
- Imbue picker: `UZL_ImbuePicker` (`UI/ItemShop/`, built in C++, no WBP), a dark box of the hero's abilities in the centre of the screen, shown before an imbue item is bought (GAS.md "Imbue"). Each choice is `ChoiceWidth` 140 wide with its icon a fixed `IconSize` 96, so long names wrap instead of stretching the icon. Added with `AddToViewport` at ZOrder 1000: the shop sits in the root layout, which is on the viewport layer too, and `AddToPlayerScreen` always draws under that whatever the ZOrder. A click on an ability buys, anywhere else cancels, and so does closing the shop (`NativeOnDeactivated`).
- Soul counter (`WBP_SoulCount`, a copy of `WBP_Weapon`, parent `UZL_HUD_Weapon`): `SoulsLabel` plus `CommonTextBlock_89`, whose `Text` binds to `ZL_VM_Attributes.GetSoulsText` through the `UZL_VMCR_Attributes` resolver. Two instances, both named `SoulCount`: `WBP_PlayerHUD` (bottom right above the minimap, padding right 24, bottom 394) and `WBP_ItemShopBase` (top right), because the shop replaces `Overlay_40` in the HUD switcher while open.
- Minimap (`WBP_Minimap`, parent `UZL_HUD_Minimap`, bottom right of `WBP_PlayerHUD`; size = its SizeBox root, 360 x 360 square): whole map, fixed orientation, drawn in `NativePaint`, letterboxed to the map shape. Layers: `PanelColor` panel, map, lanes, base diamonds, local view cone (`MakeCustomVerts` fan, `ViewConeAngle` 80, `ViewConeLength` 58), then a round hero portrait per player (`HeroIconSize` 28, local `LocalHeroIconSize` 32): ring = `AllyColor`/`EnemyColor`/`LocalColor`, disc = hero `IconColor` x 0.55, icon from `UZL_PlayerInfoBox::FindHeroData`, cached per pawn class. `bKeepOwnBaseAtBottom` rotates the map 180 deg when the local team's base is in the top half. Players come from the game state `PlayerArray`; dead pawns and pawns outside the box (Doorman hotel at Z 30000) are skipped. Fog of war: with `bHideUnseenEnemies`, an enemy shows only if an ally had line of sight (WorldStatic trace, `VisionRange` 6000 cm, every `VisionInterval` 0.2 s) in the last `RevealLinger` 1 s. This is client side and cosmetic: enemy positions are replicated regardless. No team = nobody is hostile.
  - `AZL_MinimapVolume` (`UI/HUD/`, one per map, nothing shows without it): box = map area, +X up, +Y right. `Lvl_LaneTest` has one in the persistent level, tagged `ZL_LaneTestGen`; `build_lane_test.py` replaces it with one in `_Gameplay` on a rebuild (extent 13500 x 9500 x 3500 at Z 1500). Once the sublevels are visible it collects lanes (each `AZero_ZiplineActor` spline, coloured from `LaneColors` by mean Y) and bases (average of each team's `AZero_BasePlayerStart`), then bakes the map: `Resolution` 512 on the long side, downward WorldStatic traces, `BakeBudgetMs` 4 per frame, into a transient texture it keeps (survives HUD rebuilds, can't go stale after a level rebuild). Colours by height relative to `GroundZ`: street up to `StreetMaxHeight` 120, blocks darkening to `BlockMaxHeight` 1600, pits below `PitDepth` 100, outline on steps of `EdgeHeight` 120 or next to nothing. `MapTextureOverride` skips the bake (top = +X, right = +Y). Not run on dedicated servers. No objectives exist yet, so bases are the only structure markers.
- Damage numbers: attribute set → client RPC `AZero_BasePlayerController::ShowDamageNumber` → `AZeroLockCharacter::AddDamageNumber` → `UZL_BaseDamageWidgetComponent` → `UZL_DamagePopUpBase` (1 s accumulate; BP event `AddindividualDamageNumber`, TypeID 0 spirit / 1 weapon / 2 other).
- Stamina: `UZL_HUD_StaminaBar` (`UI/HUD/`, `UCommonUserWidget`) reads the owning pawn's `UZL_VM_Attributes` every tick and builds one `UProgressBar` pip per MaxStamina point inside BindWidget `PipBox` (optional `StaminaText`). Style via `PipStyle`, `FullColor`, `RechargingColor`, `PipSize`.
- Crosshair: `UZL_HUD_PlayerBase::CF_ChargePhaseInit(VM)` swaps gun crosshair ↔ `UZL_AbilityChargePhase` in `CrosshairSwitcher`. The gun crosshair (`GunCrosshair`, `WBP_CrosshairBase`, parent `UZL_HUD_CrosshairBase`) draws itself in `NativePaint` at the centre of its geometry, in whole screen pixels: four lines (`Gap` 5, `LineLength` 7, `LineThickness` 2, `bShowTopLine`) + centre dot (`CenterDotSize` 2), `Color` white 0.95, 1 px `OutlineColor` black 0.65 outline. `bDrawCrosshair` off = draw nothing; the old designer image `Image_105` is collapsed. `SetCrosshairColor` is BlueprintCallable.

## Conventions
- Prefix `ZL_` (`UZL_*` widgets/VMs, `AZL_*` HUDs); game framework uses `Zero_`. VMs `UZL_VM_<Name>`; resolvers named inconsistently (`UZL_VMCR_*` / `UZL_*Resolver`).
- Almost all widgets derive from `UCommonActivatableWidget`; buttons `UCommonButtonBase`; children via `meta=(BindWidget)` (`BTN_*`, `B_*`).
- Assets: `WBP_` widgets, `CBS_` border styles, `CS_` text styles, `DT_` tables.
- Renaming a `UCLASS` needs a CoreRedirect (BPs reference them). Known typo names: `ZL_KeyBindingingRow`, `ZL_AbilitesTimerResolver`, `ZL_ITemIcon`, `AddindividualDamageNumber`, `LoginResultRecieved`, `TAG_INPUT_SECONDRY`.
