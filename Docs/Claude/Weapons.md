# Weapons: predicted projectiles

There is **no weapon actor/component**. Primary fire is a GAS ability (`AZeroLockCharacter::PrimaryFireAbility`) that spawns **predicted projectiles**. No hitscan, no headshots/hit zones, no recoil code, no lag compensation of targets.
Paths below are under `Source/ZeroLock/`.

## Flow of one shot
1. `AZeroLockCharacter::PrimaryFirePressed` (`ZeroLockCharacter.cpp:303`) runs a **local looping timer** at the `FireRate` attribute (seconds) → `PrimaryFireTickFunction` (`:337`) → `TryActivateAbilityByClass(PrimaryFireAbility)` while `CurrentAmmo > 0`. `ChangeFireRate` (`:330`) restarts it on attribute change.
2. `UZL_GA_WeaponFire` (`Weapon/ZL_GA_WeaponFire`, LocalPredicted, InstancedPerExecution, blocked (in `CanActivateAbility`, and `ActivationBlockedTags` via the native `TAG_WEAPON_RELOADING`) by `ZeroLock.Weapon.Reloading` and `Zerolock.Status.GooBall`) → `ApplyHeroWeaponStats` → `CommitAbility`.
   - **Ammo** (`bConsumeAmmo`, default on): `CheckCost` needs `CurrentAmmo` ≥ 1; `ApplyCost` applies native `UZL_GE_AmmoCost` (Instant, AddBase SetByCaller `Zerolock.SetByCaller.Ammo` = −shots: a burst costs `BurstCount`, pellets cost 1, capped at the ammo left) inside the activation's prediction window, so the client's count drops at once. Until 2026-10-25 `BP_BaseFireAbility` had no cost GE and ammo never went down. `PreAttributeChange` clamps `CurrentAmmo` ≥ 0.
   - **Hero weapon profile**: `AZeroLockCharacter::WeaponStats` (`FZL_HeroWeaponStats`, `Weapon/ZL_WeaponStats.h`; the Deadlock importer fills it). `WeaponStats.ProjectileClass`, when set, replaces the ability's `ProjectileClass` **and** `ServerProjectileClass` for that shot (one class for both copies), so each hero has its own bullet; the importer makes `BP_<Hero>_Projectile` (see In-flight look). With `bOverrideFireMode` the ability takes its mode from it each activation (client and server alike): `Pellets` > 1 → Shotgun (`PelletCount`, `SpreadAngle` = `PelletSpread`), else `BurstShots` > 1 → Burst (`BurstInterval`), else Single. Falloff fields: see Damage.
   - `FireMode`: Single / Burst (`BurstCount` 3, `BurstInterval` 0.07, chained `WaitDelay`) / Shotgun (`PelletCount` 8, `SpreadAngle` 6°). `BulletSpreadAngle` (default 0) uses `VRandCone` **on the client**. `BP_BaseFireAbility` (every hero's) is Shotgun 8 × 6° unless the hero's `WeaponStats` overrides it.
   - **Shoot anim**: `PlayShootMontage` once per trigger pull (before the remote-server branch, so the server plays it too and it replicates): `ShootMontage` (ability) else `DeadlockAnimSet->ShootMontage` (importer `AM_<Hero>_Shoot` from `shoot_idle`, UpperBody slot), played straight on the ASC (`PlayMontage`), not with a task, because the ability ends as soon as its projectiles spawn and the task would stop it; the next shot restarts it.
   - `GetAimData`: spawn at the hero's `WeaponStats.MuzzleSocket` (bone or socket on `GetMesh()`; importer = the bone of Deadlock's primary muzzle attachment: Lash `muzzle_flash_1`, Apollo `weaponHand_R`, Pocket/Doorman `muzzle_fx`, Solomon `weaponTip`, Viscous `muzzle_flash`), else the ability's `MuzzleSocketName`, else actor + camera-forward × `SpawnForwardOffset` (100). Aim trace from the camera (projected to character depth) against WorldStatic, Pawn, `ECC_GameTraceChannel1` ("Hero"), `MaxAimDistance` 20000; converges unless the hit is behind the muzzle.
   - Remote server starts N spawn tasks with placeholder transforms, each consuming one client packet. Ability ends when all spawns report (`OnSpawnFinished`, `:189`).
3. `UZL_Task_SpawnPredictedProjectile` (`Weapon/ZL_Task_SpawnPredictedProjectile`):
   - **Client**: optionally delays the fake spawn by `PC->GetProjectileSleepTime()`; spawns the fake `ProjectileClass`, `InitProjectileId`, adds to `PC->FakeProjectiles`, sends `FGameplayAbilityTargetData_ProjectileSpawnInfo` (location, rotation, id) via `CallServerSetReplicatedTargetData` in a scoped prediction window.
   - **Server** (`OnSpawnDataReplicated`, `:241`): `TryConsumeClientReplicatedTargetData` (custom ASC helper: one packet per task) → spawn `ServerProjectileClass` **at the client transform** → fast-forward by `GetForwardPredictionTime()` → lifespan reduced (min 0.2).
   - Listen server / standalone local player: spawns the server class directly.
   - `OnTaskRejected`: destroys the fake.
4. `AProjectile` (`Weapon/Projectile`, abstract, sreitich-style projectile prediction):
   - Components: `CollisionComp` (root sphere, profile "Projectile", environment), `HitboxComp` (capsule, "MeshHitDetection", overlap + CCD, finds targets), `TrailComp` (Cascade), `ProjectileMovement` (`UZL_ProjectileMovementComponent`, substepped 0.0166, 16 iterations; a blocking hit on an `IZL_ProjectilePortal` (Doorman's door) moves the projectile to the portal exit instead of bouncing/stopping, on every machine; `GetPortalExit` gets the collision radius so the exit is clear; `GetPortalTraversals` counts passes and `CorrectionLerpTick` skips while fake and auth counts differ). The weapon BPs (`BP_ProjectileTest`/`1`) override the missing "Projectile"/"MeshHitDetection" profiles with Custom: root WorldDynamic blocking only WorldStatic, hitbox WorldDynamic overlapping only Hero.
   - Owner client: authoritative copy links to its fake (`LinkFakeProjectile`), stays hidden; switches to auth after ping + 60 ms + `TearOffDelay` if the fake missed. An unlinked fake removes itself from `FakeProjectiles` in `Destroyed()`, so a fake that detonated and died before its auth copy replicated (normal at higher ping, e.g. point-blank wall hits) leaves no entry: the auth copy links nothing (Verbose log, no ensure) and `ShouldAuthProjDetonateOnOwner` replays the detonation with it.
   - Simulated proxies: rewind to `SpawnTransform`, replay, detonate only when `DetonationInfo` arrives (`OnRep_DetonationInfo`, keeps it visible ≥ `MinLifetime`).
   - Hits: `OnHitboxOverlapBegin` (`:559`) ignores instigator; another `AProjectile` only counts if its `HandleHitByProjectile(this)` returns true (default false; Doorman's Call Bell accepts its owner's weapon shots); LOS trace on **`ECC_Vehicle`** (reused as LOS channel), `Detonate(true)`. `OnStop` → `Detonate(false)`.
   - `Detonate` (`:748`) on server: `ApplyEffectToTarget` → AOE overlap (`ECC_WorldDynamic` + LOS) → `DetonationInfo` → `bReplicateProjectileMovement=true` → `TearOff()` (used as "detonated" signal; clients detonate in `TornOff`) → `ShutDown` (kept alive ≥0.4 s, hidden).
   - In-flight look (`BP_ProjectileTest`/`1`, 10000 cm/s, no gravity): a tracer `Sphere` static mesh (engine sphere, `M_BulletTracer`, opaque unlit) plus the `TrailComp` Cascade trail (`P_TwinBlast_Primary_Trail`, only small sparks). The tracer is a child of `CollisionComponent`, which is scaled **0.2**, so its relative scale is 5× the world size: 5 × 0.15 × 0.15 = 100 × 3 × 3 cm. Until 2026-10-26 it was 0.6 × 0.04 × 0.04 (= 12 × 0.8 cm in the world) and bullets were invisible in flight; only the impact showed.
   - Per-hero bullets (Deadlock heroes): `<Hero>/BP_<Hero>_Projectile`, a copy of `BP_ProjectileTest` (config `template_projectile`) made once by `ue_import.py` `build_projectile` and then left alone, so tune speed etc. on the asset. Seeded from Deadlock's weapon: `InitialSpeed`/`MaxSpeed` = `m_flBulletSpeed` × cm per unit (2.54 × mesh scale ≈ 1.78), gravity scale = `m_flBulletGravityScale` × `deadlock_gravity` (800 u/s², Source's default, **assumed**) × 1.78 / 980, `InitialLifeSpan` = `m_flRange` / speed (bullets vanish at Deadlock's range). Speeds in units/s: Lash 25000 (gravity 0.8), Pocket 22000 (0.8), Solomon 14000, Viscous 10000, Doorman 8000, Apollo 5000 (range 1000: short reach).
   - FX: `HitCharacterParticle` / `HitWorldParticle` (Cascade), `FProjectileFX DetonationFX` (Niagara pooled, sounds, force feedback, decal; `ZeroAbilityTypes`).
5. Damage (server only): `ApplyEffectToTarget` applies only on **direct hit with `bApplyWeaponDamage`** → `UBaseCharAbilitySystemComponent::ApplyWeaponDamage(TargetASC, Damage)` (`GAS/BaseCharAbilitySystemComponent.cpp:59`): `GE_WeaponClass` with SetByCaller `Zerolock.DamageCalc.Weapon`, checks `IsUntouchable`, sends `Event.WeaponHit`. `Damage` = `WeaponDamage`, or with **`bUseShooterWeaponStats`** (primary-fire bullets only, set on `BP_ProjectileTest`/`1`; leave it off for ability projectiles) the shooter's `BulletDamage` attribute (fallback `WeaponDamage` when 0) × `WeaponStats.GetFalloffScale(distance from SpawnTransform to the hit)`: full damage to `FalloffStartRange`, linear to `FalloffEndScale` at `FalloffEndRange` (cm; end ≤ start = off).
6. Ammo / reload: when `CurrentAmmo` drops to 0 (`PostAttributeChange`, only on the **locally controlled** machine: the server also pressing it for a remote player raced the client) → `AZeroLockCharacter::Reload()` = input press of `ReloadAbility` (`BP_BaseReloadAbility`, `UZero_BaseReloadAbility`, LocalPredicted, InstancedPerActor, input R). The reload: refused on a full clip; holds `ZeroLock.Weapon.Reloading` (ActivationOwnedTags, native) which blocks firing; duration = `ReloadTime` attribute (fallback the ability's `ReloadTime` 1 s); plays `ReloadMontage` (ability, else `DeadlockAnimSet->ReloadMontage`, importer-made `AM_<Hero>_Reload` on the `UpperBody` slot) with `PlayMontageAndWait` at rate = length / duration (replicates to other players); at the end the server applies `ReloadEffect` (`GE_ReloadEffect`, `UCalc_Reload`: CurrentAmmo = MaxAmmo). Only the server replicates its end (the client's timer can finish first and would cancel the server's refill).

## Prediction tuning
`AZero_BasePlayerController` (`Zero_BasePlayerController.cpp:81-100`), values in `Config/DefaultGame.ini:42-46`:
`ForwardPredictionTime = 0.001 × ClientBiasPct(0.5) × clamp(ExactPing − (local ? 0 : PredictionLatencyReduction 20), 0, MaxPredictionPing 120)`.
Projectile ids from `FakeProjectileIdCounter` (starts at 1; `NULL_PROJECTILE_ID` = 0).

## AProjectile defaults (ctor `Projectile.cpp:83-124`)
`InitialLifeSpan` 5, replicates, `bReplicateProjectileMovement` false (true on detonation), `NetPriority` 2, `MinNetUpdateFrequency` 100, `bPredictFX` true, `MaximumBounces` 1, `WeaponDamage` 1, `bApplyWeaponDamage` false, `AreaRadius` 0, `TearOffDelay` 0.1, `MinLifetime` 0.05 (Config=Game, no ini section). Push-model replication: `ProjectileId`/`ZeroPlayerController` OwnerOnly; `SpawnTransform`/`DetonationInfo`/`InitialOwnerAimRotation` SimulatedOnly.
Also the base for hero projectiles (Pocket Barrage/FlyingCloak, Doorman CallBell…).

## Legacy
- `UZero_BaseWeaponAbility` + `AZero_BaseProjectile`: non-predicted, server-only spawn, `DrawDebugLine` every shot (`Zero_BaseWeaponAbility.cpp:64`), only `CommitAbilityCost`, damage hard-coded 1 (`Zero_BaseProjectile.cpp:88`), doesn't replicate by default. Still copied by Xayah's projectile.

## Known issues
- **Trust**: server spawns at the client-supplied transform with no distance/direction check (`ZL_Task_SpawnPredictedProjectile.cpp:259-274`); spread rolled on client; **fire rate is a client timer**, server limited only by `CommitAbility` (cooldown GE, if any, is BP-only).
- No friendly-fire check in `ApplyEffectToTarget` (check the GE execution).
- `ImpactGameplayEffect`, `AreaGameplayEffect`, `bUseFilter`, `MissedImpactFX`, `BounceFX` do nothing; `MakeEffectSpec` returns empty (`:1003`); AOE loop applies nothing (`:1020` returns when not direct).
- `Projectile.cpp:202` dead check (`if (!(!(cond), TEXT(...)))` comma operator); `:191` derefs `GetOwner()` when invalid; `:633-638` lambda captures a stack `FTimerHandle` by reference; `:214`, `:817`, `Zero_BasePlayerController.cpp:91` unchecked PlayerState deref; `:1081`, `:503` possible /0; `checkf(1, …)` at `:304`.
- Fake-position correction is a no-op when the auth projectile is ahead (negative speed into `VInterpConstantTo`, `:445-506`; only with `bCorrectFakeProjectilePositionOverTime`).
- Burst/shotgun server tasks share one target-data delegate; if the client sends fewer packets, the server ability waits on remote data until GAS times out.
- Magic numbers: 0.4 s post-detonation life (`:351`), 100 cm miss threshold (`:963`), +60 ms (`:817`), 0.0005×ping catch-up (`:214`), `ECC_GameTraceChannel1` = Hero (`ZL_GA_WeaponFire.cpp:166`).
