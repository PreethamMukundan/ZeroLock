# Hero kit: data-driven hero abilities

Code: `Source/ZeroLock/{Public,Private}/HeroKit/` (+ hero folders `KaijuX/`, `LadyGrimm/`). Built 2026-11-13 to implement the hero design sheet (19 heroes, "Characters" Google Sheet) without one C++ class per ability: most abilities are a **BP child of a kit class with its numbers filled in**. Hero content: `Content/ZERO/Heroes/<Hero>/` (layout below). Everything here is **untested in play**; numbers are first guesses.

## Payload (`ZL_KitTypes.h`)
`FZL_KitPayload` = what one hit does to one hero. Zero/empty = off. `ZLKit::ApplyPayload(Source, Hero, Target, Origin, Payload, Scale)` (server):
- Hostile only: `Damage` (`DamageType` Spirit/Weapon/Melee via the ASC `Apply*Damage`, Source = damage source for telemetry), `ExecuteBelowHealthPercent` (kills at or below that % after the damage; 100 = always, via a 1e6 spirit hit), `DotPerSecond`/`DotDuration` (`UZL_ItemProcComponent::AddDot`).
- Friendly only (incl. self): `Heal`, `HealMaxHealthPercent`, `Barrier`/`BarrierDuration` (`AddCombatBarrier`), `bCleanse`.
- Anyone: `bStripBarrier` / `bStealBarrier` (zero the target's `CombatBarrier`, steal gives it to the caster for `StolenBarrierDuration`), `Stats` for `StatDuration` (`UZL_GE_ItemStatsTimed`, the item stat list: `MoveSlowPercent` -30 = slow, `FireRatePercent`, `MoveSpeed`...), `Statuses` for `StatusDuration` (`ZLItemStatus::Apply`; Stun and Root also send the victim's status bar), `TimedTags` for `TagDuration` (any tag through `UZL_GE_ItemStatus`), `KnockbackSpeed`/`KnockUpSpeed`/`KnockbackDuration` (away from Origin, `Zerolock.Movement.Forced` victim event; negative speed pulls), `bPullToOrigin` (`PullTo`), `CooldownDelay` (s added to running cooldowns, `AdjustActiveEffectsDurationByValue`).
- Untouchable enemies are skipped entirely. Damage/heal/barrier/DoT × Scale (each ability's `PowerScale`, a level curve).
`FZL_KitArea` (Shape Sphere/Cone/Line, `Range` cm × ability range scale, `Angle` = cone half angle or line half width, `bRequireLineOfSight` WorldStatic) + `ZLKit::FindHeroes` (Hero object type, `EZL_KitTeam` Enemies/Allies(+self)/AlliesNotSelf/Everyone). `ZLKit::DrawArea` debug.

Engine changes made for it: `EZL_ItemStatus::Root` (appended; `ZeroLock.Movement.Rooted`), native tags `Zerolock.Status.Immortal` (attribute set treats it like buddha: hero damage stops at 1 HP) and `Zerolock.Status.IgnoreBarrier` (on the attacker: its damage skips the target's combat barrier), `AZeroMoverPawn::IsJumpInputHeld()`.

## Kit classes
| Class | Base | Does |
|---|---|---|
| `UZL_Kit_Ability` | `UBaseGameplayAbility` | Press: `SelfPayload` on the caster → optional predicted self move (`MoveForwardSpeed`/`MoveUpSpeed`/`MoveDuration`, `bMoveAlongPitch`, `bStopAfterMove`) → after `HitDelay`, `PulseCount` area hits every `PulseInterval` (`Area` at `ForwardOffset`, `EnemyPayload`, `AllyPayload`, `bAllyPayloadOnSelf`; `RandomStrikeSpread` = each pulse at a random spot; pulses after the first follow the caster). `ActiveDuration` keeps it active (ActivationOwnedTags, progress bar `bShowProgressBar`, `bEndOnRepress`) and while active `WhileActiveHitPayload` goes on whoever the caster damages (`WhileActiveTriggers`, default bullets + melee; `WhileActiveHitChance`). Client end never replicates (QuickAoE pattern). `bCutUpSpeedAfterMove` + `UpSpeedAfterMove` (2026-11-15): at the end of the self move the owner latches one 0.02 s ability move = the move's flat velocity + `UpSpeedAfterMove` up (predicted), so a launch stays short instead of coasting up on its leftover up speed; `bStopAfterMove` wins if both are set. `bMoveAlongInput` (2026-11-14): the self move's flat direction = `GetInputWorldDir()` (WASD, camera-relative) when held, like Apollo's Sigil, else the aim. Cue networking (2026-11-15, Side Step showed its launch/landing clouds only on the listen server): a pulse at the press (`HitDelay` 0) runs on the server inside the activation's prediction window, so GAS's cue multicast skips the predicting owner; the owner now plays `PulseCue` itself in `ActivateAbility` (like `CastCue`). The landing cue: the server plays it under `FScopedPredictionWindow(ASC, activation key, false)` (multicast skips the owner) and the owning client plays it locally (`ZLKitCue::ExecuteLocal`) when it lands. `bLandingHit` (event-based since 2026-11-15): every machine binds its Mover's `OnMovementModeChanged`; a change from an air mode to Walking or Sliding is the landing (Ziplining isn't), so double jumps and air dashes just extend the wait. The caster counts as off the ground if cast in the air, else once the leap switches to Falling (the server simulates the leap a bit after its activation). Resimulated mode changes count too (only the server hits). `LandingTimeout` (default and Side Step 10 s) is only a safety cap that ends the ability with no hit. Before this a 0.05 s `IsOnGround()` poll capped at 3 s ended Side Step mid-air (~3.5 s arc) and skipped the hit. On touchdown the server hits `Area` around the caster with `LandingPayload` (+ `LandingCue`) and the ability ends (the normal pulses still run, e.g. a launch hit at the press). Hooks: `DoPulse`, `OnPulseHitEnemy`, `OnKitActivated`, `OnWhileActiveHit`. |
| `UZL_Kit_ProjectileAbility` | `UBaseGameplayAbility` | Predicted `AZL_Kit_Projectile`s at the crosshair: `Count` in a `FanAngle` fan, `PitchOffset`, `VolleyCount` volleys `VolleyInterval` apart (× `VolleyIntervalScale` each), `FireDelay`; optional self payload / self move (leap then throw). `Hit` (`FZL_KitProjectileHit`: `DirectPayload`, `AreaRadius` + `AreaPayload` + `AreaAllyPayload`, `Zone` + `ZoneClass`), `AreaRadiusPerVolley`. Remote server starts every spawn task at activation (Xayah pattern); the server copy is armed in the spawn callback. Ends when all spawned. **Manual fire** (`bFireOnConfirm`, 2026-11-14): each left click (generic confirm, re-bound per shot because the ASC clears its confirm callbacks; weapon fire skips while bound) fires one volley, up to `VolleyCount`, within `ConfirmWindow` s (`UZL_WaitDelay_Task` progress bar, starts at activation, first click after `FireDelay`); `bCancelOnJump` (jump consumed) / `bCancelOnRepress` end it; the client's end is replicated in this mode (spawn data goes first), the server only ends on its own after the last spawn or a safety timer (`FireDelay + ConfirmWindow + 3`). `HoldModeName` (e.g. "Locked", Lash Death Slam style hover: no gravity, holds still): queued with `QueueNextMode` on every machine after `MoveDuration` (or at once with no self move), "Falling" in `EndAbility`; direct mode queues aren't in the predicted input stream (Movement.md hazards), same as Death Slam. |
| `AZL_Kit_Projectile` | `AProjectile` | BP child sets speed, gravity, bounces, life, hitbox, `PlaceholderColor` (engine sphere). `HitTeam` (others fly through), `bPierce` (each hero once, no detonation), `ReturnAfter` (boomerang: turns home after N s or at the first wall, ignores walls coming back, ends near the caster), `bZoneOnFloor`. `bPassThroughWalls` (root ignores WorldStatic; with `bPierce` = beam through walls and heroes). `bSteerToCrosshair` (`SteerTurnRate` 240°/s, `SteerDelay` 0.1, `SteerRange` 8000): turns toward the caster's crosshair point every tick; each copy computes it (owner: camera trace; server: Mover `LookDir` from the view location; other clients: `GetBaseAimRotation`), so proxies may drift; damage is the server's. Detonation (hero, wall, life end) → `Explode`: area payloads + zone. |
| `AZL_Kit_Zone` | `AActor` | Replicated disc (engine cylinder, `Color`); server pulses `FZL_KitZoneSpec`: `Duration`, `Radius`, `Interval`, enemy/ally payload, `bTriggerOnce` mine (`ArmDelay`, `TriggerRadius`), `StrikeRadius` (each pulse one random spot: arrows/lightning), `bFollowCaster`, `MaxPerCaster` (oldest goes; keyed by ability class). `Spawn(...)`, `SnapToFloor`. |
| `UZL_Kit_GroundAbility` | `UZL_BaseSurfaceTargetAbility` | Aiming shows a flat disc of the hit radius on the spot (`bShowAreaPreview`, `GetPreviewDiscRadius` → `AZL_GATA_SurfaceTrace::PreviewDiscRadius`: engine cylinder lying on the surface, green/red). Pick ground → after `ImpactDelay`: `ImpactRadius` hit (enemy/ally payloads) and/or `Zone`. `SelfPayload`. |
| `UZL_Kit_TargetAbility` | `UZL_BaseConeTargetAbility` | One hero (TargetTeam etc. from the base) → `TargetPayload` × `PulseCount` (`HitDelay`, `PulseInterval`, on the hero's timers), `SelfPayload`, `Move`: DashToTarget / TeleportBehind / SwapPlaces (`ServerForceTeleport`) / PullTargetToCaster. Hooks `OnTargetConfirmedServer`, `GetPulsePayload`. |
| `UZL_Kit_DashAbility` | `UZL_BaseDashAbility` | `HitPayload` per enemy passed (DashDamage default 0), `SelfPayload` at the start, `bFlatDash`. |
| `UZL_Kit_Passive` | `UBaseGameplayAbility` | `DefaultAbilities`, ServerOnly, auto-activates. `Procs` (`FZL_ItemProc` list run by the hero's `UZL_ItemProcComponent` through a transient `UZero_Item_data`), `PermanentStats` (infinite `UZL_GE_ItemStats`), `PermanentTags` (server loose tags), `OnKillPayload` + `OnKillChance` (`Event.Kill`). Death cancels it, respawn restarts it, so per-life counters reset. Hooks `OnPassiveStarted/Ended`, `OnKill`. |

## Effects (`ZL_KitCue.h`): Niagara only, through gameplay cues
Abilities never spawn effects directly. They hold `FZL_KitCue` (`Cue` tag `GameplayCue.HeroKit.<Hero>.<Ability>.<Role>`, `Duration`); the notify asset with that tag owns the look: `UZL_GCN_KitBurst` (`UGameplayCueNotify_Static`, executed) or `AZL_GCN_KitLoop` (`AGameplayCueNotify_Actor`, added/removed, attached to the target), both with `FZL_KitCueVisual` (`NiagaraSystem`, `Sound`, `Scale` (× radius / `ReferenceRadius` with `bScaleWithRadius`; radius = the cue's `RawMagnitude`), `ForwardOffset`/`UpOffset` along the cue's facing (`Normal`), `bAttachToTarget`, `FloatParameters` (Niagara user floats), `RadiusParameter` (default `Radius`: the cue radius ÷ scale, since Niagara shapes are in component space)). Notifies live in `Content/ZERO/Heroes/<Hero>/FX/GCN_<Ability>_<Role>`, made by the builder.
`ZLKitCue::Play(ASC, Cue, Location, Facing, Radius)`: `Duration` 0 = `ExecuteGameplayCue` on that ASC (inside an ability's activation on the owner it's predicted, the server's multicast skips them); `Duration` > 0 (server) = `AddGameplayCue` + `RemoveGameplayCue` after it (replicated loop on that hero). `AddLocal`/`RemoveLocal`/`ExecuteLocal` = `UGameplayCueManager::*_NonReplicated` on any actor every machine already simulates. Hooks: `FZL_KitPayload::HitCue` (on the target's ASC); `UZL_Kit_Ability` `CastCue` (owner + server, predicted) and `PulseCue` (server, each pulse origin, radius = area); `UZL_Kit_ProjectileAbility` `CastCue` (predicted); `UZL_Kit_TargetAbility` `CastCue`; `UZL_Kit_GroundAbility` `ImpactCue`; `UZL_Kit_DashAbility` `DashCue`; `AZL_Kit_Projectile` `ImpactCue` (server, caster's ASC, radius = explosion), `bHidePlaceholder`; `FZL_KitZoneSpec` `LoopCue` (local loop on the zone, tag replicated initial-only as `VisualLoopCue`), `PulseCue` (each pulse/strike/mine, caster's ASC), `bHideDisc`. **`AProjectile`** (all projectiles, weapon bullets too) gained `TrailCue` (local loop, added in `BeginPlay`, removed in `ShutDown`/`Destroyed`) and `HitCharacterCue`/`HitWorldCue` (local execute in `Detonate`, next to the Cascade particles, every machine that shows the detonation). The builder clears the Cascade `TrailComp` template and hit particles on hero bullet copies. `UZL_Kit_Passive::OnHitPayload` (+ `OnHitChance`, `OnHitCooldown`, `OnHitTriggers`) carries a payload with a `HitCue`; it's skipped when the payload and cue are empty.
Niagara sources, `/Game/ZERO/HeroKit/FX/`: `M_HeroKit_Ice` (particle colour, fresnel glow, Niagara mesh/sprite usage; made headlessly by `Tools/HeroKit/make_fx_assets.py`), `Niagara/NS_HeroKit_IceSpikes` (one mesh emitter: engine cone, pivot at its base, ice material; user params `SpikeCount` (burst), `Radius` (flattened sphere shape), `Height` (ScaleMeshSize = (0.32, 0.32, 1) × Height/100, rising over the first 11% of life and sinking over the last 20%), `Lifetime`; velocity, gravity, drag and rotation modules off; authored through the MCP Niagara toolset), `Niagara/NS_<name>` = Niagara conversions of Paragon effects (`make_fx_assets.py` `CONVERT` list, through the **CascadeToNiagaraConverter** plugin, enabled in `ZeroLock.uproject`; it needs the editor UI: run `py "E:/Repo/ZeroLock/ZeroLock/Tools/HeroKit/make_fx_assets.py"` in the editor, the commandlet asserts in `Finalize`). **Converted systems are pruned and their materials flagged** (2026-11-14, through MCP): the converter copies every Cascade emitter (the grenade explosion had 31: rocks, smoke, sparks, lights), and the Paragon materials lacked the Niagara usage flags (`bUsedWithNiagaraSprites/Ribbons/MeshParticles`), so the game drew the default grey material ("Material ... missing usage flag NiagaraSprites!
