# Hero kit: data-driven hero abilities

Code: `Source/ZeroLock/{Public,Private}/HeroKit/` (+ hero folders `KaijuX/`, `LadyGrimm/`). Built 2026-11-13 to implement the hero design sheet (19 heroes, "Characters" Google Sheet) without one C++ class per ability: most abilities are a **BP child of a kit class with its numbers filled in**. Hero content: `Content/ZERO/Heroes/<Hero>/` (layout below). Everything here is **untested in play**; numbers are first guesses.

## Payload (`ZL_KitTypes.h`)
`FZL_KitPayload` = what one hit does to one hero. Zero/empty = off. `ZLKit::ApplyPayload(Source, Hero, Target, Origin, Payload, Scale)` (server):
- Hostile only: `Damage` (`DamageType` Spirit/Weapon/Melee via the ASC `Apply*Damage`, Source = damage source for telemetry), `ExecuteBelowHealthPercent` (kills at or below that % after the damage; 100 = always, via a 1e6 spirit hit), `DotPerSecond`/`DotDuration` (`UZL_ItemProcComponent::AddDot`).
- Friendly only (incl. self): `Heal`, `HealMaxHealthPercent`, `Barrier`/`BarrierDuration` (`AddCombatBarrier`), `bCleanse`.
- Anyone: `bStripBarrier` / `bStealBarrier` (zero the target's `CombatBarrier`, steal gives it to the caster for `StolenBarrierDuration`), `Stats` for `StatDuration` (`UZL_GE_ItemStatsTimed`, the item stat list: `MoveSlowPercent` -30 = slow, `FireRatePercent`, `MoveSpeed`...), `Statuses` for `StatusDuration` (`ZLItemStatus::Apply`; Stun and Root also send the victim's status bar), `TimedTags` for `TagDuration` (any tag through `UZL_GE_ItemStatus`), `KnockbackSpeed`/`KnockUpSpeed`/`KnockbackDuration` (away from Origin, `Zerolock.Movement.Forced` victim event; negative speed pulls), `bPullToOrigin` (`PullTo`), `CooldownDelay` (s added to running cooldowns, `AdjustActiveEffectsDurationByValue`).
- Untouchable enemies are skipped entirely. Damage/heal/barrier/DoT × Scale (each ability's `PowerScale`, a level curve).
`FZL_KitArea` (Shape Sphere/Cone/Line, `Range` cm × ability range scale, `Angle` = cone half angle or line half width, `bRequireLineOfSight` WorldStatic) + `ZLKit::FindHeroes` (Hero object type, `EZL_KitTeam` Enemies/Allies(+self)/AlliesNotSelf/Everyone). `ZLKit::DrawArea` debug.

Engine changes made for it: `EZL_ItemStatus::Root` (appended; `ZeroLock.Movement.Rooted`), native tags `Zerolock.Status.Immortal` (attribute set treats it like buddha: hero damage stops at 1 HP) and `Zerolock.Status.IgnoreBarrier` (on the attacker: its damage skips the target's combat barrier), `AZeroMoverPawn::IsJumpInputHeld()`.

## Kit classes
| Class | Base | Does |
|---|---|---|
| `UZL_Kit_Ability` | `UBaseGameplayAbility` | Press: `SelfPayload` on the caster → optional predicted self move (`MoveForwardSpeed`/`MoveUpSpeed`/`MoveDuration`, `bMoveAlongPitch`, `bStopAfterMove`) → after `HitDelay`, `PulseCount` area hits every `PulseInterval` (`Area` at `ForwardOffset`, `EnemyPayload`, `AllyPayload`, `bAllyPayloadOnSelf`; `RandomStrikeSpread` = each pulse at a random spot; pulses after the first follow the caster). `ActiveDuration` keeps it active (ActivationOwnedTags, progress bar `bShowProgressBar`, `bEndOnRepress`) and while active `WhileActiveHitPayload` goes on whoever the caster damages (`WhileActiveTriggers`, default bullets + melee; `WhileActiveHitChance`). Client end never replicates (QuickAoE pattern). Hooks: `DoPulse`, `OnPulseHitEnemy`, `OnKitActivated`, `OnWhileActiveHit`. |
| `UZL_Kit_ProjectileAbility` | `UBaseGameplayAbility` | Predicted `AZL_Kit_Projectile`s at the crosshair: `Count` in a `FanAngle` fan, `PitchOffset`, `VolleyCount` volleys `VolleyInterval` apart (× `VolleyIntervalScale` each), `FireDelay`; optional self payload / self move (leap then throw). `Hit` (`FZL_KitProjectileHit`: `DirectPayload`, `AreaRadius` + `AreaPayload` + `AreaAllyPayload`, `Zone` + `ZoneClass`), `AreaRadiusPerVolley`. Remote server starts every spawn task at activation (Xayah pattern); the server copy is armed in the spawn callback. Ends when all spawned. |
| `AZL_Kit_Projectile` | `AProjectile` | BP child sets speed, gravity, bounces, life, hitbox, `PlaceholderColor` (engine sphere). `HitTeam` (others fly through), `bPierce` (each hero once, no detonation), `ReturnAfter` (boomerang: turns home after N s or at the first wall, ignores walls coming back, ends near the caster), `bZoneOnFloor`. Detonation (hero, wall, life end) → `Explode`: area payloads + zone. |
| `AZL_Kit_Zone` | `AActor` | Replicated disc (engine cylinder, `Color`); server pulses `FZL_KitZoneSpec`: `Duration`, `Radius`, `Interval`, enemy/ally payload, `bTriggerOnce` mine (`ArmDelay`, `TriggerRadius`), `StrikeRadius` (each pulse one random spot: arrows/lightning), `bFollowCaster`, `MaxPerCaster` (oldest goes; keyed by ability class). `Spawn(...)`, `SnapToFloor`. |
| `UZL_Kit_GroundAbility` | `UZL_BaseSurfaceTargetAbility` | Pick ground → after `ImpactDelay`: `ImpactRadius` hit (enemy/ally payloads) and/or `Zone`. `SelfPayload`. |
| `UZL_Kit_TargetAbility` | `UZL_BaseConeTargetAbility` | One hero (TargetTeam etc. from the base) → `TargetPayload` × `PulseCount` (`HitDelay`, `PulseInterval`, on the hero's timers), `SelfPayload`, `Move`: DashToTarget / TeleportBehind / SwapPlaces (`ServerForceTeleport`) / PullTargetToCaster. Hooks `OnTargetConfirmedServer`, `GetPulsePayload`. |
| `UZL_Kit_DashAbility` | `UZL_BaseDashAbility` | `HitPayload` per enemy passed (DashDamage default 0), `SelfPayload` at the start, `bFlatDash`. |
| `UZL_Kit_Passive` | `UBaseGameplayAbility` | `DefaultAbilities`, ServerOnly, auto-activates. `Procs` (`FZL_ItemProc` list run by the hero's `UZL_ItemProcComponent` through a transient `UZero_Item_data`), `PermanentStats` (infinite `UZL_GE_ItemStats`), `PermanentTags` (server loose tags), `OnKillPayload` + `OnKillChance` (`Event.Kill`). Death cancels it, respawn restarts it, so per-life counters reset. Hooks `OnPassiveStarted/Ended`, `OnKill`. |

Hero-specific C++: `KaijuX/ZL_KaijuX_Abilities` (`UZL_GE_KaijuX_Mark` 8-stack infinite mark, `UZL_KaijuX_Alpha` marks on every hit (`OnDamageDealt`, 0.25 s per target), `UZL_KaijuX_ImStarving` +`DamagePerMark`, execute at `ExecuteMarks`, eats the marks, `UZL_KaijuX_PlasmaFist` stores 2× damage taken up to 400), `LadyGrimm/ZL_LadyGrimm_Abilities` (`UZL_GE_LadyGrimm_SoulOrb` 3 stacks, `CursedAura` +1 orb per pulse that hits, `Necromancer` spends all: 1 HoT / 2 big heal on lowest-health ally / 3 AoE heal + damage; `SoulLink` mirrors her health loss onto the cursed enemy for `LinkDuration`), `HeroKit/ZL_HeroPassives` (Yatagarasu `SunlitVigil`, JA594 `Gateway` + `UnholyMachine`, Genghis `CruelWarmonger` (team kill difference from `AZero_BasePlayerState::Kills`, capped `MaxStacks` 10), Ashura `Monarch`, Ryu `BeastAwakens` (`AbilityCommittedCallbacks`), Kronos `LoopingPast` (0.25 s health history), Mephisto `SpatialRift` (mark, re-press within `RiftWindow` teleports them to the aim), Tempest `WindRider` (LocalOnly: loose `Zerolock.Status.Floating` while jump is held and falling → Mover Float glide)), Kai Koa `FrozenFist` (`UZL_KaiKoa_FrozenFist`: `FrostTriggers` (light + heavy melee) add `StacksPerHit` stacks of `UZL_GE_KaiKoa_Frost` (AggregateByTarget, ClearEntireStack, each new stack restarts the timer; the passive sets each spec's duration to `FrostDecayTime` 3 s, so all stacks go 3 s after the last one; it grants `DebuffStackTag` (default `Zerolock.DebuffStack.Frost`) so the stacks show on the HUD, GAS.md "Debuff stacks") with `StackCue`, 0.2 s per-target cooldown; at `StacksToFreeze` 3 the frost clears and `FreezePayload` (Stun + Root 1.5 s, Frozen ice cue) lands; no new frost while frozen)).

## Effects (`ZL_KitCue.h`): Niagara only, through gameplay cues
Abilities never spawn effects directly. They hold `FZL_KitCue` (`Cue` tag `GameplayCue.HeroKit.<Hero>.<Ability>.<Role>`, `Duration`); the notify asset with that tag owns the look: `UZL_GCN_KitBurst` (`UGameplayCueNotify_Static`, executed) or `AZL_GCN_KitLoop` (`AGameplayCueNotify_Actor`, added/removed, attached to the target), both with `FZL_KitCueVisual` (`NiagaraSystem`, `Sound`, `Scale` (× radius / `ReferenceRadius` with `bScaleWithRadius`; radius = the cue's `RawMagnitude`), `ForwardOffset`/`UpOffset` along the cue's facing (`Normal`), `bAttachToTarget`, `FloatParameters` (Niagara user floats), `RadiusParameter` (default `Radius`: the cue radius ÷ scale, since Niagara shapes are in component space)). Notifies live in `Content/ZERO/Heroes/<Hero>/FX/GCN_<Ability>_<Role>`, made by the builder.
`ZLKitCue::Play(ASC, Cue, Location, Facing, Radius)`: `Duration` 0 = `ExecuteGameplayCue` on that ASC (inside an ability's activation on the owner it's predicted, the server's multicast skips them); `Duration` > 0 (server) = `AddGameplayCue` + `RemoveGameplayCue` after it (replicated loop on that hero). `AddLocal`/`RemoveLocal`/`ExecuteLocal` = `UGameplayCueManager::*_NonReplicated` on any actor every machine already simulates. Hooks: `FZL_KitPayload::HitCue` (on the target's ASC); `UZL_Kit_Ability` `CastCue` (owner + server, predicted) and `PulseCue` (server, each pulse origin, radius = area); `UZL_Kit_ProjectileAbility` `CastCue` (predicted); `UZL_Kit_TargetAbility` `CastCue`; `UZL_Kit_GroundAbility` `ImpactCue`; `UZL_Kit_DashAbility` `DashCue`; `AZL_Kit_Projectile` `ImpactCue` (server, caster's ASC, radius = explosion), `bHidePlaceholder`; `FZL_KitZoneSpec` `LoopCue` (local loop on the zone, tag replicated initial-only as `VisualLoopCue`), `PulseCue` (each pulse/strike/mine, caster's ASC), `bHideDisc`. **`AProjectile`** (all projectiles, weapon bullets too) gained `TrailCue` (local loop, added in `BeginPlay`, removed in `ShutDown`/`Destroyed`) and `HitCharacterCue`/`HitWorldCue` (local execute in `Detonate`, next to the Cascade particles, every machine that shows the detonation). The builder clears the Cascade `TrailComp` template and hit particles on hero bullet copies. `UZL_Kit_Passive::OnHitPayload` (+ `OnHitChance`, `OnHitCooldown`, `OnHitTriggers`) carries a payload with a `HitCue`; it's skipped when the payload and cue are empty.
Niagara sources, `/Game/ZERO/HeroKit/FX/`: `M_HeroKit_Ice` (particle colour, fresnel glow, Niagara mesh/sprite usage; made headlessly by `Tools/HeroKit/make_fx_assets.py`), `Niagara/NS_HeroKit_IceSpikes` (one mesh emitter: engine cone, pivot at its base, ice material; user params `SpikeCount` (burst), `Radius` (flattened sphere shape), `Height` (ScaleMeshSize = (0.32, 0.32, 1) × Height/100, rising over the first 11% of life and sinking over the last 20%), `Lifetime`; velocity, gravity, drag and rotation modules off; authored through the MCP Niagara toolset), `Niagara/NS_<name>` = Niagara conversions of Paragon effects (`make_fx_assets.py` `CONVERT` list, through the **CascadeToNiagaraConverter** plugin, enabled in `ZeroLock.uproject`; it needs the editor UI: run `py "E:/Repo/ZeroLock/ZeroLock/Tools/HeroKit/make_fx_assets.py"` in the editor, the commandlet asserts in `Finalize`). **Converted systems are pruned and their materials flagged** (2026-11-14, through MCP): the converter copies every Cascade emitter (the grenade explosion had 31: rocks, smoke, sparks, lights), and the Paragon materials lacked the Niagara usage flags (`bUsedWithNiagaraSprites/Ribbons/MeshParticles`), so the game drew the default grey material ("Material ... missing usage flag NiagaraSprites! Default Material will be used in game" in the log). Kai's systems now keep only the water emitters (trails: the ribbon only; the Twinblast bullet-shell cone `SM_Twinblast_SimpleUltBullet` rendered as a bare cone (its look relies on dynamic material parameters the conversion doesn't drive), so don't keep it; hits: flare, spray, droplets; steam: mist + spray; ExplodeWater: droplets + spherical droplets; BounceSplash: droplets. **No mesh emitters on the Twinblast water conversions**: `M_Shockwave_Refract` (pure refraction) shows as a clear unshaded shape, and the splash/foam/cylinder mesh materials read Dynamic Parameters the conversion doesn't drive, so they all looked like bare cones and were removed; GroundSlam: smoke, both shockwaves) and the base materials they use carry the flags (saved in `Content/Paragon*`). A newly converted system needs both steps again: `RemoveEmitter` the noise, then set the flag on the **base** material (walk `Parent` from instances), recompile, save. `NS_TwinBlast_VortexGrenade_Explode_Summer` is unpruned and no longer used. Kai changes the same day (spec + BPs): Arctic Burst is one 60 damage burst (slow 40% 1.5 s), shown as an ice-spike ring instead of the grenade explosion; Absolute Zero is one 900 cm sphere around Kai after 0.2 s (no random strikes): 90 damage, Stun + Root 3 s, ice spikes on each frozen enemy for the full 3 s. `cue()` now always writes `scale_with_radius`, so rebuilding a cue doesn't keep a stale `true`.
Spec helpers in `hero_specs.py`: `cue(role, system, scale, radius, forward, up, attach, duration, sound, params, loop)`, `ice(role, count, height, spread, life, ...)`; `gen_tags.py` writes the cue tags. Done so far: Kai Koa (2026-11-14).

## Heroes (`Content/ZERO/Heroes/<Hero>/`, `Tools/HeroKit/`)
`hero_specs.py` holds every hero's abilities as data (parent class + property values); `build_heroes.py` (editor Python, headless or `py` in the editor; optional hero names as arguments; reparents an existing BP whose parent changed, and a spec value `None` resets that property to the C++ default, which clears overrides a reparented BP kept) creates or updates: `BP_<Hero>` (copy of `BP_SCombo`: Wukong placeholder mesh and anims, Mover setup), `DA_<Hero>_Hero` (name, description, icon colour), `GE_<Hero>_DefaultStats` (copy of SCombo's: every hero has the same base stats until tuned in the Hero Workbench), `Weapon/BP_<Hero>_Weapon` (copy of `BP_SCombo_Weapon`: fire mode, pellets, spread) firing `BP_<Hero>_Bullet`/`_Bullet_Server` (copies of `BP_ProjectileTest`/`1`: speed, gravity, life, bounces), `Abilities/<Ability>/BP_<Hero>_<Ability>` (+ `_Projectile`), a `DT_HeroList` row only for heroes in `hero_specs.SELECTOR_HEROES` (just `KaiKoa` since 2026-11-14: the other 18 are built but hidden from hero select; add a name there and rerun the builder to list one). `gen_tags.py` writes `Config/Tags/HeroKitTags.ini` (cooldown tag `ZerolockAbilities.Cooldown.<Hero>.<Ability>` per slotted ability); run it before the builder.
Slot mapping (the sheet has 7 entries; chosen by the user 2026-11-13): normal attack → `PrimaryFireAbility`; secondary → `SecondryFireAbility` (slot 1); ability 1 → `Ability_1` (slot 2); ability 2 → `Ability_2` (slot 3); ult → `UltimateAbility`; passive → `DefaultAbilities`. The sheet's **f** abilities are built (`Abilities/<F>/`, with a cooldown tag, no `Slot`) but **not assigned** to the hero: the user decides where they go. Right mouse stays aim zoom.
**Not built (need new tech, slot left empty):** Kai Mist Shroud; Tempest Rebound, Alley-oop; Kaiju Titan King, Plasma Beam; Ayiana Monkey Bars, Slippery Slope, Let's Swing; Grimm I Am Death (abyssal rabbit is an instant heal, no doppelganger, no ally heal on the scythe); Yatagarasu Flash Bang, Photon Shield, Wrath, Eclipse; Scarab Skin Shed; Van Helsing Full Moon; Jet Predator's Instinct, Dragons Can Fly; JA594 Demonic Binding; Sobek Breath of Life, Crown of Wisdom, Nun Descent, Sebek-khu Stele, God of Water; Genghis King's Blade, Tactician, Garid, Trusty Steed; Ashura dice (primary has no dice), Mad Hounds, Curse of Mexico; Ryu Vermillion Bird; Dr. Ooze Jello Monster, Emergency Getaway; Ryuga Dark Force, Supreme Overload, Supreme Flight, Life Destructor; Mephisto Void; Kronos Past Echo, I Am Paradox, Rewritten Time; WuKong Flying Nimbus, Golden Hair. Primaries are plain bullets tuned per hero (melee-ish primaries are short-life shotguns).

## Known issues / not done
- Nothing tested in play. Damage pipeline still drops friendly damage, so Jet's self-burn and Ashura's "allies alike" only hit enemies.
- `bPierce` projectiles: fake and server track hits separately; a proxy may show a pierce the server didn't count (cosmetic).
- Boomerang return steers every copy toward the caster locally; proxies can drift (cosmetic, damage is server).
- Gateway, Rift and other two-press abilities keep their state per machine; a mispredicted first press can desync the second.
