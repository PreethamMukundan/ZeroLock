# GAS: abilities, attributes, damage, items

Paths under `Source/ZeroLock/`. Hero-specific abilities: see Heroes.md.

## Architecture
- **ASC lives on the pawn.** `AZeroLockCharacter : AZeroMoverPawn, IAbilitySystemInterface` creates `UBaseCharAbilitySystemComponent "AbilitySystemComp"` (replicated, **Mixed**), `UBaseCharAttributeSet "AttributeSet"`, `UZero_Item_Inventory_Component "ItemInventory"` (`ZeroLockCharacter.cpp:46-52`). Owner = Avatar = pawn. `AZero_BasePlayerState` only holds TeamID/K/D/A.
- `InitAbilityActorInfo(this,this)` in `PossessedBy` (server), `OnRep_PlayerState` (client), `ResetCharacter`.
- Server init order (`PossessedBy`): InitAbilityActorInfo → `CreateVM_Att` → `InitializeAttributes()` (`:163`: applies BP `DefaultGameplayEffect` at L1 (per hero: `HeroAbilities/<Hero>/GE_<Hero>_DefaultStats`, Content.md); tag listeners `ZeroLock.Stun`→`Stunned`, `ZeroLock.Abilities.MovementLock`→`MovementLocked` (empty), `ZeroLock.Melee.Parry`→`Parry`; attribute delegates for health/speed/ammo) → `GiveAbilities()` (`:207`) → `InitializeFloatingStatusBar`.
- **Granting** (server, `GiveAbilities`): per-slot `TSubclassOf` properties on the character BP (`ZeroLockCharacter.h:206-233`), no hero data asset.
  - `DefaultAbilities[]` at L1 (passives, `UZL_StatusTimerAbility`, which every hero needs).
  - `PrimaryFireAbility` at L1.
  - `GrantAbilityOfClassX(Class, InputID, bBroadcast)` (`:240-273`) for `SecondryFireAbility`, `AltFireAbility`, `Ability_1`, `Ability_2`, `UltimateAbility`, `ReloadAbility`, `HeavyMeleeAbility`, `LightMeleeAbility`, `ParryAbility`: spec at **level 0** (= not yet upgraded; `LevelUpAbility` raises it), input tag `Zerolock.InputBindTags.*` in **DynamicSpecSourceTags** (UI slot lookup + cooldown matching), Passive TargetStyle → InputID None.
- **Input**: classic InputID enum `EGASAbilityInputID` (`ZeroLock.h:22-39`: None, Confirm, Cancel, Primary_Attack, Secondry_Attack, Ability_1, Ability_2, Ultimate, Melee, Parry, Reload, LightMelee, AltFire, Item_1..4; append new values at the end). Enhanced Input handlers call `AbilityLocalInputPressed/Released`. Primary fire is a local timer (Weapons.md). Note `Secondry` is an ability slot (key E / 1, UI `Slot_Secondary`), not right click.
- **Alt fire** (right mouse): `EI_AltFire` (defaults to `IA_AltFire`, remappable, keybind category Combat) → InputID `AltFire` → `AltFireAbility` (GAS category on the hero BP, no UI slot, no input tag). Defaults to `UZL_GA_AimZoom` (`GAS/ZL_GA_AimZoom`): Deadlock's zoom, hold to zoom, LocalOnly, camera only (`AZeroMoverPawn::SetAimZoom`, Movement.md "Camera"); `ZoomFOVRelative` -40 (Deadlock `m_flZoomFOV_Relative` of `hero_weapon_base`), `ZoomBlendTime` 0.15. No move slow (Deadlock `m_flZoomMoveSpeedPercent` 1.0) and no spread or sensitivity change. Heroes whose Deadlock weapon has `m_bCanZoom = false` have an alt-fire weapon instead (Solomon `chessmaster`, Viscous; Apollo and Doorman have `_alt` weapons but still zoom) and set their own `AltFireAbility`. The importer gives each Deadlock hero `BP_<Hero>_AltFire` (Blueprint child of `UZL_GA_AimZoom`, `ZoomFOVRelative` from the weapon's `m_flZoomFOV_Relative`, `--weapons-only`) and warns for heroes that can't zoom. RMB is also `IA_Cancel`: `AltFirePressed` does nothing while `GenericLocalCancelCallbacks` is bound (a targeted cast waiting for confirm/cancel), so the press only cancels. `EGASTargetConfirmationStyle`: Instant, Quick, Confirm, Passive.
- **Prediction**: hero abilities mostly LocalPredicted; passives/self-buffs ServerOnly; status timers ServerInitiated. All damage/heal/soul changes server-only via ASC helpers. Custom client→server data: `ServerReportSlamLocation` (keyed by prediction key, `UZL_Task_WaitSlamLocation`), `TryConsumeClientReplicatedTargetData` (projectiles), replicated InputReleased events (`UZL_WaitChargeRelease_Task`). Victim movement = gameplay event to the victim's ASC → small ability → Mover `RequestSafe*` (Movement.md).

## Attribute set: `UBaseCharAttributeSet` (only one)
All replicated `COND_None` (health and charges `REPNOTIFY_Always`). Percent stats are whole numbers (20 = 20%).

- `PreAttributeChange`: MaximumHealth change → `AdjustAttributeForMaxChange` (up: current += delta; down: clamp; first init: current = max).
- `PostGameplayEffectExecute` (`.cpp:57-193`): **Damage**: both sides `AZeroLockCharacter` with PlayerStates and **different TeamID** (friendly fire ignored) → read & zero `Damage` → `Damage.Tag.NonLethal` caps at 1 HP → `SourcePC->ShowDamageNumber` (full damage) → `CombatBarrier` absorbs first → subtract the rest from health → `AddLastHit` (assists) → `HandleDeath()` at 0. **Healing**: clamp add, no team check. Clamps for health, regen, charges.
- `PostAttributeChange`: `FireRate` → `ChangeFireRate()`; `CurrentAmmo <= 0` → `Reload()`.
- **Regen and combat state**: server timer `AZeroLockCharacter::HealthRegenStep` every `HealthRegenInterval` 0.25 s. `MarkInCombat` runs on both heroes when hero damage lands in `PostGameplayEffectExecute`; `OutOfCombatDelay` (8 s, a guess: tune it on the hero BP) later the replicated loose tag `Zerolock.Status.OutOfCombat` (`TAG_STATUS_OUT_OF_COMBAT`) goes on. Regen writes `CurrentHealth` directly, so it skips `ApplyHeal`: no heal events, no `HealingBonus`, but it stops under `Zerolock.Status.HealBlocked`. A respawn counts as out of combat. Heroes with a `HealthRegeneration` in their default stats GE regen from now on.
- **Effect durations**: `UBaseCharAbilitySystemComponent::ApplyGameplayEffectSpecToSelf` copies the spec and rescales HasDuration effects: × (1 + caster's `DurationExtension`) if the context has an ability and this isn't its cooldown; × (1 − `DebufReduction`) if the source is an enemy. `UZL_GE_MoveSlow` is Infinite, so slows use `SlowResistance` instead.
- Death: `HandleDeath` (once) → CancelAllAbilities, remove effects, DisableInput, `ServerHandleDeath` → GameFlow.md. Respawn: `ResetCharacter` (remove effects, re-init, re-activate passives, full health).

### Deadlock stats (importer)
`GE_<Hero>_DefaultStats` from the importer (Animation.md "Hooking up a hero") overrides: `EMaxHealth` → `CurrentHealth` + `MaximumHealth`, `EBaseHealthRegen` → `HealthRegeneration`, `EStamina` → `MaxStamina`, `EStaminaRegenPerSecond` → `StaminaRegenRate`, `EBulletArmorDamageReduction` → `WeaponResistance`, `ETechArmorDamageReduction` → `SpiritResistance` (0 when absent), `ELightMeleeDamage` / `EHeavyMeleeDamage` → `LightMeleeDamage` / `HeavyMeleeDamage`, weapon `m_flBulletDamage` → `BulletDamage`, `m_flCycleTime` → `FireRate`, `m_iClipSize` → `MaxAmmo` + `CurrentAmmo`, `m_reloadDuration` → `ReloadTime`. Not in the GE: pellets / burst / falloff → the BP's `WeaponStats` (`apply_weapon_stats`, ranges × 1.778 cm/unit), walk / crouch / dash speed → the Mover settings (`apply_movement`, Movement.md). `CurrentSpeed`, `CurrentJump`, `WeaponDamage`, `SpiritDamage`, `Soul` keep the template's values. The import logs every Deadlock value that has no attribute. Deadlock values (Lash/Apollo/Pocket/Solomon/Doorman/Viscous): health 780/770/780/780/755/780, regen 2/1/1/2/1/2, stamina 3 (Solomon 2), regen 0.222/s, spirit resist Lash 10, Pocket −15; weapon cycle 0.2625/0.38/0.525/0.5/0.63/0.21 s, clip 29/15/11/8/8/20. The hand-made `ZERO/HeroAbilities/<Hero>Test/GE_<Hero>_DefaultStats` (100 HP, 30 ammo, 1 s fire rate, all the same; Solomon used Lash's) are what the hero BPs use until `--stats-only` is run.

## Damage pipeline
1. Server caller: `SourceASC->ApplyWeaponDamage | ApplySpiritDamage | ApplyMeleeDamage(TargetASC, value, DamageSource = nullptr)` (pass `this` from abilities/projectiles: telemetry groups damage by that class, Telemetry.md) (`BaseCharAbilitySystemComponent.cpp:59-135`): `IsUntouchable` → authority → spec of BP-set `GE_<Type>Class` (L1) with SetByCaller `Zerolock.DamageCalc.Weapon|Spirit|Melee` → apply → `Event.<Type>Hit` to self, `Event.<Type>Recieved` to target (+ client RPC to victim owner).
2. GE asset (BP) runs `UCalc_WeaponDamage` / `UCalc_Spirit_Damage` / `UCalc_Melee_Damage` (`GAS/Calculations/`). The calcs **capture the Source's `Damage` attribute**, so the GE must feed SetByCaller into that capture (verify in asset).
   - Weapon: `base = Damage + FlatWeapon`; `unmit = base × (1+WeaponDamage/100) × (1+UniversalDamage/100)`; `mit = unmit × (1 − (WeaponRes − WeaponResReduction)/100)`.
   - Spirit: same with spirit stats. Melee: `D + D×WeaponDamage/100×0.5 + D×MeleeDamage/100`, × universal, mitigation (see issues).
   - Adds dynamic tag `Damage.Tag.Weapon|Spirit|Melee` (damage-number styling); lifesteal heal applied inside the calc; outputs to target `Damage`.
   - No crits, headshots or falloff.
3. `PostGameplayEffectExecute` applies it (above).
- Healing: `ApplyHeal` → `GE_HealingClass`, SetByCaller `Zerolock.HealCalc.Healing` → `UCalc_Healing`: 0 if `Zerolock.Status.HealBlocked`; `heal × (1 + HealingBonus/100 − HealingReduction/100)`.
- Reload: `UCalc_Reload` sets CurrentAmmo = source MaxAmmo.

## ASC: `UBaseCharAbilitySystemComponent`
- Delegates `OnNewAbilityAdded(Spec)` (also rebroadcast for every spec on each `OnRep_ActivateAbilities`), `OnAbilityUpgraded`.
- `LevelUpAbility`, `ApplyGameplayEffect(Target, Class, Level)`, `ApplyGameplayEffectWithStacks`, `IsUntouchable` (`Zerolock.Untouchable`, sends `Event.UntouchableTrigger`).
- `SendGameplayEventToSelf` / `SendGameplayEventToTarget` (also client RPC to a remote victim's owner).
- `AdjustActiveEffectsDurationByPercentage` / `ByValue` (server): rescales active HasDuration GEs whose captured source tags include `ZerolockAbilities.Cooldown` or `Zerolock.InputBindTags` (cooldown reduction/refresh).
- Slam location plumbing, `TryConsumeClientReplicatedTargetData`, mutable active-effect accessors.

## Target actors (`GAS/TargetActors/`)
- `AZL_GATA_SurfaceTrace : AGameplayAbilityTargetActor_Trace`: location targeting. Line trace from the player's camera against **WorldStatic only** (pawns never block), clipped to `MaxRange` (default 2000) around the hero. `SurfaceMode` (`EZL_SurfaceTargetMode`): `Ground` = normal within `MaxGroundAngle` (45°) of up, no drop to the floor when aiming at a wall; `Wall` = normal within `WallAngleTolerance` (20°) of horizontal; `Any` = all angles incl. ceilings. Output: `SingleTargetHit` (read with `GetHitResultFromTargetData`: `ImpactPoint` + `ImpactNormal`). Reticle gets `SetIsTargetValid` and is placed on the surface, Z aligned to the normal. **Placement preview**: the owning C++ ability can set `PlacementCheck` (`TFunction<bool(const FHitResult&, FTransform&)>`: turns the hit into the real placement transform, starting from hit point + X = normal, and returns whether it's allowed; ANDed into validity, runs every aim tick) and `PreviewBox` (placement-space box, cm): `PreviewComponent` shows `PreviewMesh` (engine Cube; any mesh: its bounds are fitted onto the box, or with `bFitPreviewMeshToBox` off it keeps its size with the pivot on the placement; model it X out of the surface) at the placement, `PreviewMaterial` (engine `BasicShapeMaterial`, "Color" param) `ValidPreviewColor` green / `InvalidPreviewColor` red, only for the locally controlled `PrimaryPC`, only on surfaces `SurfaceMode` allows (Wall mode: hidden while aiming at the floor), no collision/shadow. Per ability: make a BP subclass of `AZL_GATA_SurfaceTrace` with its own `PreviewMesh`/`PreviewMaterial`/colors and set it as the ability's target actor class (Doorway: `TargetActorClass`); `PreviewBox` comes from the ability (Doorway: door bounds). `bDebug` draws the green/red sphere only when no preview is shown. Optional no-clip rules: `Clearance` (`FZL_PlacementClearance`, `GAS/TargetActors/ZL_PlacementClearance.h`, **off by default**, needs a valid `PreviewBox` as the footprint; client aim only, the ability must re-check on the server). The struct (placement space, X out of the surface, WorldStatic only): `bEnabled`; box overlap over the footprint extended to `FrontClearance`, starting `SurfaceInset` 2 off the surface and `FloorInset` 8 off the bottom; `bRequireFlushSurface` (3×3 traces must find the surface within `MaxSurfaceGap` behind, normal dot ≥ 0.9); `bRequireGround` (ground under both bottom sides within `MaxGroundStep`). `IsClear(World, Placement, Footprint, IgnoredActor)` is usable from any ability (Doorway's `DoorClearance`).
- Optional anchor: `MaxAnchorDistance` > 0 makes hits further than that from `AnchorLocation` invalid; hits on `InvalidActors` are invalid (Doorway's second door).
- Invalid confirm: `Confirm` style re-binds `GenericLocalConfirmCallbacks` (`LocalInputConfirm` clears them) and keeps aiming; `Instant`/`Quick` or `bCancelOnInvalidConfirm` cancel. Client-produced data: the server trusts the location.

## Items (shop)
- `UZero_Item_data` (`Items/`, PrimaryDataAsset): ItemID, Cost, SellRefundPercent (0.5), name/icon/description, `PassiveEffects` (GE), `GrantedAbilities`, `ItemType` (Weapon/Spirit/Vitality), `ItemTierType` (1–5; the shop lists Tier 5 in the Tier 4 row), `NextItemsToUpgrade`, `Stats` (`FZL_ItemStatValue` list). Assets `Content/Data/Items/ZL/<Type>/Tier<n>/DA_<source id>`, table `DT_ZL_Items`, both built by `Tools/ItemImporter` (Content.md). `Content/Data/Items/Generated` and `DT_MasterItems` are the old set: no costs or effects, no longer used by the shop.
- `UZL_GE_ItemStats` (`Items/`): the one Infinite effect behind every `Stats` list, a SetByCaller modifier per `EZL_ItemStat` named `ItemStat_<n>` (`FName` number = enum value + 1), so items need no GE asset. `SetMagnitudes` sets all of them, 0 for flat stats and 1 for percent ones. Percent stats: `AmmoPercent` and `StaminaRegenPercent` are `MultiplyAdditive`; `FireRatePercent` is `DivideAdditive` because `FireRate` is seconds between shots; bonuses add before applying. Spirit Power maps to `SpiritDamage`, 1 point = 1%. Hand-made `PassiveEffects` still work alongside it.
- `UZL_GE_ItemStatsTimed`: the same stats for a limited time, what actives apply (the applier calls `SetDuration`). A stat may feed several attributes (`AbilityCharges` → all four `MaxCharges`): same `ItemStat_<n>` name on each row.
- `UZL_GE_Item_PassiveEffect`: Infinite-duration base GE.
- **Active items** (`Items/ZL_GA_ActiveItem`): `UZero_Item_data::Active` (`FZL_ActiveItem`: `Target` Self/Ally/Enemy/Ground, `Cooldown`, `Range`, `Radius`, `AreaTeam`, `Damage` (spirit), `Heal`, `Barrier` + `BarrierDuration`, `TimedStats` + `Duration`) needs no ability asset. `UZero_Item_Inventory_Component::GrantActiveAbility` gives a spec of `UZL_GA_ActiveItem_Self` (LocalPredicted, commits, then server `ZLActiveItem::Execute`), `_Target` (on `UZL_BaseConeTargetAbility`; Ally can self-cast by double tap or with nobody in the cone) or `_Ground` (on `UZL_BaseSurfaceTargetAbility`), with the item as the spec's **source object** and `Item_1..4` as input ID; `OnGiveAbility` sets the instance's cooldown from it. `Radius` > 0 hits every `AreaTeam` hero around the cast point instead of the target (no line of sight check). Everyone hit gets everything, so actives that hit enemies only carry negative stats (`read_active` in `build_items.py` drops the rest); `CasterStats` and `CasterStatuses` are the caster's alone. Also `Delay` (a timer before `ExecuteNow`), `HealMaxHealthPercent`, `Dot*` (`UZL_ItemProcComponent::AddDot`), `ZoneDuration` + `ZoneDamagePerSecond` (`AddZone`: an invisible area at the cast point, ticks with the procs), `DashDistance` and `bDashToTarget` (`Zerolock.Movement.PullTo` on the caster in 0.15 s, `FindDashEnd` stops 60 cm short of walls), `LaunchSpeed` (`Zerolock.Movement.Forced`), `bPullToPoint`. Item effects have no visuals or sounds yet.
- **Slots**: four, `FZeroInventoryItem::ActiveSlot` (replicated), lowest free key on buy, `GetActiveItem(Slot)`. An upgrade inherits the key and cooldown of the active it replaces; a fifth active is refused. `ServerMoveActiveItem(From, To)` moves an item to another key, swapping with any item there: it only rewrites the spec's `InputID`, so nothing is re-granted. Cooldown tags (`ZerolockAbilities.Cooldown.Item.Slot1..4`, `ZLActiveItem::GetCooldownTag`) go by `FZeroInventoryItem::CooldownSlot`, not the key: it's fixed while the item is owned and rides on the spec's dynamic tags, so a running cooldown follows the item to its new key. Selling clears it. Keys: `AZeroLockCharacter::ItemInputActions` (soft refs to `IA_Item1..4`, Z, X, V, G; made by `ue_import_items.py`, remappable under "Items").
- **Item procs** (`Items/ZL_ItemProcComponent`, on the hero as `ItemProcs`, server only): `UZero_Item_data::Procs` (`FZL_ItemProc`) is every passive effect as data, so items need no ability or effect asset. One `Trigger` (`EZL_ProcTrigger`: Bullet/Spirit/Melee/HeavyMelee hit, Bullet/Spirit/Damage taken, Parry, AbilityCast, UltimateCast, Periodic, While, Aura), optional conditions (`Cooldown`, `Chance`, `MinDamage` alone or over `DamageWindow`, `BuildUpHits` per target, own `HealthAbove`/`Below`, `TargetHealthAbove`, `MinRange`/`MaxRange`) and actions (`BonusDamagePercent`, `SpiritDamage`, `TargetHealthPercent`, `PercentOfHit`, `Heal`, `HealPercentOfDamage`, `Barrier`, `SelfStats`, `TargetStats`, `Duration`, `MaxStacks`, `Radius` + `MaxTargets` + `AreaTeam` + `bSkipHitTarget`, `Dot*`, `Status`, `bCleanse`). `Apply*Damage` multiplies the hit by `GetDamageScale` (procs with `BonusDamagePercent` do nothing else, so an item with more needs a second proc), then `FinishHit` sends `NotifyEvent` to both heroes with `LastDamageDealt`: what the hit did after resists, set by `PostGameplayEffectExecute`, so friendly or blocked hits fire nothing. `Event.*Hit` carries the same amount as `EventMagnitude`. `bFiring` stops a proc's own damage triggering procs (the target's Taken procs still run). A 0.25 s timer runs While, Aura, Periodic and damage over time. A `TargetStats` effect is one per target per proc: a new hit removes and re-applies it with `Stacks`. While with `Duration` 0 and Aura use the infinite `UZL_GE_ItemStats`, removed when the condition ends or the item goes. `ResetAfterRespawn` forgets handles, since a respawn strips the effects.
- **Headshots**: no bones involved. `AProjectile::ApplyEffectToTarget` asks `AZeroLockCharacter::IsHeadshot(HitPoint)`: the top `HeadshotHeight` (0.2) of the capsule. It sets `bHeadshotHit` on the shooter's ASC around `ApplyWeaponDamage`, which adds the `Headshot` trigger to `BulletHit`. Headshots do nothing without an item: there's no base bonus. Server positions, so a fast target's head can be a little off from what the shooter saw.
- **Imbue**: `UZero_Item_data::bImbue` + `ImbueStats`. `UZL_ItemShop_Base::ItemPressed` shows `UZL_ImbuePicker` (`UI/ItemShop/`, built in C++, added with `AddToViewport` above the shop) when `NeedsImbueChoice`; a click on an ability calls `ServerBuyImbuedItem(Item, InputID)`, a click elsewhere cancels. It only accepts `Secondry_Attack`, `Ability_1`, `Ability_2`, `Ultimate`. `FZeroInventoryItem::ImbueInputID` replicates; `ServerBuyItem` refuses an imbue item with no ability, and an upgrade keeps the one it replaces with no picker. `UBaseGameplayAbility::GetImbueBonus(Stat)` reads `GetImbueBonus` from the inventory, so it works on clients: `GetCoolDownTime` (`CooldownReduction`), `GetAbilityRangeScale` (`AbilityRange`), `GetEffectDurationScale` (`AbilityDuration`). `ImbuedCast` and `ImbuedHit` procs only react for their own item's ability (`NotifyEvent`'s `ImbueInput`). `ImbuedHit` needs the ability itself as `DamageSource`, so damage from a projectile an ability fired doesn't count.
- **Item statuses** (`ZLItemStatus` in `Items/ZL_GE_ItemStats`, `EZL_ItemStatus`, `FZL_ActiveItem::Statuses` or `FZL_ItemProc::Status`): `UZL_GE_ItemStatus` carries one tag for `StatusDuration`. Silence `Zerolock.Status.Silenced`: `CanActivateAbility` refuses `Secondry_Attack`, `Ability_1`, `Ability_2`, `Ultimate` (items still work, running abilities aren't interrupted). Disarm `Zerolock.Status.Disarmed`: refuses the hero's `PrimaryFireAbility`. Stun: `TAG_STUN`. BulletImmune `Zerolock.Status.BulletImmune`: `ApplyWeaponDamage` returns before anything happens. Unstoppable `Zerolock.Status.Unstoppable`: removes then blocks `GetCrowdControlTags` (stun, silence, disarm, root) in `ApplyGameplayEffectSpecToSelf`. Stealth `Zerolock.Status.Stealthed`: `AZeroLockCharacter::StealthChanged` hides the mesh and overhead bar locally for viewers on the other team; ends on any hit or any hero ability or weapon use (`BreakStealth`), but not on items or zoom. Invulnerable: `TAG_UNTOUCHABLE`. Enlarged and Shrunk (`Zerolock.Status.Enlarged`/`Shrunk`): `SizeStatusChanged` scales the mesh by `EnlargedScale` 1.2 / `ShrunkScale` 0.5 on every machine; the capsule stays full size. `CleanseDebuffs` removes timed effects from enemies; infinite ones such as `UZL_GE_MoveSlow` belong to their applier and stay.
- `UZero_Item_Inventory_Component` (on character): replicated `Items` (MaxSlots 12, `OnRep_Items` fires `ItemDelegate` on clients). `ServerBuyItem`: refuses owned items and items something owned was built from; owned items that list this one in `NextItemsToUpgrade` are consumed and credited at full `Cost` (the server works these out, its `ItemUpgradedFrom` parameter is ignored); the upgrade takes the lowest consumed slot. `ServerSellItem` refunds `Cost × SellRefundPercent`. Souls change through the `Soul` base value. `ReapplyItemEffects` restores stat GEs and restarts passive item abilities after `ResetCharacter`, which removes every active effect. Queries for UI: `HasItem`, `GetOwnedComponents`, `IsUpgradedAway`. Inventory lives on the pawn, so a hero swap starts empty.

## New ability recipe
1. Pick a base: montage+notify → `UZL_BasePlayAnimation_AndDo`; reticle → `UBase_GA_TargetActors` (pick one hero in a cone, incl. ally/self-cast → `UZL_BaseConeTargetAbility`; one location on a surface → `UZL_BaseSurfaceTargetAbility`); projectile → `UZL_GA_WeaponFire`-style predicted task (Weapons.md) or `UZL_BaseProjectileThrowAbility`; else `UBaseGameplayAbility`.
2. `Public/<Hero>/ZL_<Hero>_<Name>.h` + `Private/<Hero>/ZL_<Hero>_<Name>.cpp`. Tunables as `FScalableFloat` by level (spec level starts at 0).
3. Server-only effects: `Hero->GetMyAbilitySystemComp()->ApplySpiritDamage(Villan->GetMyAbilitySystemComp(), Damage, this)`; victim moves via `SendVictimMoveEvent`; self moves via Mover tasks / `RequestSafe*`; status bars via `SendStatusTimer`.
4. Add `ZerolockAbilities.Cooldown.<Name>` to `DefaultGameplayTags.ini`.
5. BP subclass in `Content/ZERO/HeroAbilities/<Hero>/<Name>/`: CooldownTags, CooldownDuration, Slot, name/icon/descriptions, montage/event tag, charges.

7. Don't hold `ZeroLock.Abilities.*` tags unless you want to block every other ability.
