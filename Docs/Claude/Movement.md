# Movement: Mover stack, input, networking

Paths under `Source/ZeroLock/`. Heroes are **Mover pawns, not ACharacters** (no CharacterMovementComponent).

## Stack
`AZeroLockCharacter` → `AZeroMoverPawn` (APawn + `IMoverInputProducerInterface`) → `UZeroMoverComponent` (`UCharacterMoverComponent`).
- Modes and transitions are configured in **Blueprint** (`Content/ZERO/monkeyBoi/BP_Mover_Monkey` MoverComponent; also `BP_ZeromoverPawn`, `BP_Deadlock_*`): modes `walking`, `falling`, `flying`, `sliding` (`UZeroSlideMode`), `melee` (`UZeroMeleeMode`), `ziplining` (`UZeroZiplineMode`), `locked` and `floating` (`UZeroFloatMode`); **component-level** transitions (checked every tick in every mode) `UZeroSlideTransition`, `UZeroMeleeTransition`, `UZeroZiplineTransition`. `StartingMovementMode` Falling.
- Per frame: Enhanced Input caches state on the pawn → `ProduceInput_Implementation` (fixed tick) writes `FCharacterDefaultInputs` + `FZeroMovementInputs` → `UZeroMoverComponent::OnMoverPreSimulationTick` applies layered moves / effects / mode queues → active mode simulates.
- Network prediction (`Config/DefaultNetworkPrediction.ini`): Fixed tick 60 Hz, simulated proxies Interpolated (100 ms buffer), `FixedTickInputSendCount=6`. Pawn `bReplicates`, `SetReplicatingMovement(false)`.

## AZeroMoverPawn (`Mover/ZeroMoverPawn`)
- Capsule 34/88, mesh at (0,0,−88) yaw −90, SpringArm 400 (pawn control rotation).
- Input assets (BP): `DefaultMappingContext`, `MoveAction`, `LookAction`, `JumpAction`, `CrouchAction`, `DashAction`, `MeleeAction`, `ZiplineAction`. Melee and Zipline are bound on **Triggered** (every frame while held).
- `OnJumpInputPressed` native multicast + `ConsumeJumpPress()` lets abilities swallow a jump (Pocket Barrage, EnchantersSatchel).
- `DeadlockAnimSet` (Animation.md).
- `GetSyncedAimRotation`, `GetInputWorldDir`: **buggy**, see issues.

## UZeroMoverComponent (`Mover/ZeroMoverComponent`)
`OnMoverPreSimulationTick` order: begin step (resim detection, stamina settings) → crouch intent from input (**before** `Super`, which applies the stance) → `Super` → rooted from input `bIsRooted` (+teleport, return) → exit `RootedModeName` on the unroot frame → (in `MeleeModeName` "Melee": no mantle/dash/jump) mantle (jump held, not while dashing; on success skips jump/dash only) → dash (costs stamina) → jump counter reset + air jump / wall bounce (skipped while a dash is active or this frame mantled/dashed) → slide-exit ease → ability linear move (Walking/Sliding → Falling) → dynamic move-to-actor → release → stop → pull → teleport. `HandlePostMovement` (bound to `OnPostMovement`) writes `FZeroMoverSimState` into the end sync state in the same step.
- **Prediction rules** (each was causing rollbacks in a recorded play session): read start-of-step velocity/location via `GetSimStartVelocity/Location()` (cached from the previous step's end state and on rollback; `GetSyncState()` is stale during resimulation and when several sim steps run in one frame). Use `IsResimulatingStep()` for cosmetics: the `TimeStep` given to the pre/post-sim hooks never has `bIsResimulating` set, so `GetLastTimeStep().bIsResimulating` is always false there. Facing inside the sim comes from `LookDir` (input), not the actor (actor yaw is set by the controller outside the sim and differed by up to 107° on the server). `bHandleJump` is off (the base class queued a second jump impulse on every ground jump).

**"Safe latch" API** (how gameplay code moves a pawn): `RequestSafeAbilityMove(Velocity, Duration)`, `RequestSafeDynamicAbilityMove(Actor, Duration)`, `RequestSafePullTo`, `RequestSafeStop` (100 ms zero), `RequestSafeRelease` (Locked → Falling), `RequestSafeTeleport`. Each sets a latch that the next `ProduceInput` copies into `FZeroMovementInputs`, so it is predicted. `ShouldIgnoreServerLatch()` makes the **server ignore these for remote-client-controlled pawns**: the owning client must make the same request.
Abilities also call `QueueNextMode("Locked"/"Falling"/FloatingModeName)` directly (Apollo ItaniLoSahn/Riposte, Lash DeathSlam, Pocket Barrage/EnchantersSatchel, `ZL_WaitChargeRelease_Task`). That isn't part of the predicted input stream.

## Data structs (`Mover/ZeroMovementData.h`)
- `FZeroMovementInputs` (custom NetSerialize): `LookDir`, `bWantsToCrouch`, `bCustomJumpJustPressed`, `bJumpHold`, `bWantsToZipline`, `bWantsToDash`, `bWantsToMelee`, ability move (velocity, duration), dynamic move (actor, duration), pull (target, duration), `bWantsStop`, `bWantsRelease`, teleport (target), `bIsRooted`. `MoveInput` and `bSlideIntentValid` are never used.
- Sync state: `FZeroMoverSimState{Stamina, AirJumpsUsed, AirDashesUsed, DashRemainingMs, bWasRooted, bWasSliding}` (persistent type, added in the component ctor and again in `InitializeComponent` if a BP list lacks it), `FZeroMeleeSyncState{ElapsedTimeMs}`, `FZeroZipliningState{ZiplineActor, bMovingToEnd}`. `FZeroSlideState`, `FZeroDashState` unused.

## Known issues
- Slide: landing buffer unreachable (`ZeroSlideTransition.cpp:22`, `IsOnGround()` false in Falling; landing goes Falling → Walking → Sliding and needs ≥300 cm/s). Slide mode has no gameplay tags (`IsOnGround()` false while sliding), no floor/ledge check (keeps sliding in mid-air, air jumps keep resetting), no max duration; `SlideJumpImpulse` unused; header defaults disagree with ctor.
- `GetSyncedAimRotation` reads input from the sync state → always actor rotation (projectile aim has no pitch where used: `Zero_BaseWeaponAbility.cpp:36`, `ZL_Apollo_FlawlessAdvance.cpp:174`). Use `GetLastInputCmd()`.
- `GetInputWorldDir`: server returns zero for remote clients; local path includes pitch (`ZeroMoverPawn.cpp:283-299`).
- Melee/zipline sync state not reset on re-entry (second lunge ends after one tick; zipline reuses the old actor). Zipline transition and mode trace differently (mode radius 1000 to 10000); `ZeroInputs` null deref (`ZeroZiplineMode.cpp:142`); debug sphere in mode.
- Prediction hazards: direct `QueueNextMode` from abilities (Apollo ItaniLoSahn/Riposte, Lash DeathSlam, Pocket Barrage, `ZL_WaitChargeRelease_Task`) runs at different sim frames on client and server, so every entry/exit causes a rollback. Route them through input the way `bIsRooted` works.
- One-shot input flags (`bCustomJumpJustPressed`, `bWantsToDash`, latches) are fragile: when the server is starved of input it re-runs the previous cmd (engine `NetworkPredictionService_Input.inl:146`, can repeat a jump/dash), and on buffer overflow it skips cmds (`:135`, can drop one). A request counter in the input plus a last-handled counter in `FZeroMoverSimState` would make them exactly-once.
- Stamina max/regen are read from GAS attributes each step; a replicated change lands on the client later than on the server (one correction). Effects that set the `Stamina` attribute directly are overwritten by the mover.
- Feel / rules (found 2026-10-11, not fixed): wall bounce is free and unlimited (no counter, no stamina) and its `BlockAllDynamic` sweep counts other pawns as walls; melee lunge ends with zero velocity (dead stop, drops straight down in air); no coyote time or jump buffer (a jump just after walking off a ledge is an air jump); jump in Float/Melee-like non-Walking/Falling modes counts as a free ground jump (Melee now blocked); mantle traces (`BlockAll`) hit pawns; zipline direction uses actor forward instead of `LookDir` (`ZeroZiplineMode.cpp:96`); slide entry boost has no cooldown (crouch-tap spam).
- Trust: the client decides `bIsRooted`, so a modified client can ignore roots.
- Choppy online movement = frame hitches, not the net code. On the server it shows as `LogNetworkPrediction: Gap in input stream detected on server` / `Recovering from input stream starvation`; on the client as `Invalid interpolation frames. Copying old content forward` (the 100 ms `FixedTickInterpolationBufferedMS` buffer runs dry). Seen 2026-10-19 with two uncooked `UnrealEditor.exe -game` instances on one PC, which compile shaders and load assets on demand. Judge smoothness on cooked builds or separate PCs (`stat unit`, `t.MaxFPS 60`) before raising the interpolation buffer or the input send count.
- The MoverExamples map teleporter (`L_CharacterMovementBasics` `TriggerVolume_10`) teleports outside the input stream, which causes large corrections. Example content only.
- Debug tool: `Saved/MoverRec/rec.py` (editor Python, `py "<path>" start|stop` during multiplayer PIE) logs per-frame pawn state, rollbacks and mode changes to CSV.
- Trust: latched moves aren't validated (except teleport distance). Server-only `RequestSafe*` on remote victims is dropped (`ZL_Lash_GroundStrike.cpp:170-177`, which also passes a displacement as velocity).
- Stun/Parry `DisableInput` can leave cached input stuck. `CurrentSpeed` attribute doesn't affect Mover. Assist map never inserts (`ZeroLockCharacter.cpp:426-430`). `LastHitCharacter`/`AssistListCharacters` marked Replicated but not registered.
- `FZeroMovementInputs` is large and sent 6× per input. Game and editor targets disagree on build settings / include order.
